# 城市顶部状态栏 / 公司 EXP 方案 v2

> 对比稿：`city-top-hud-funds-supply-exp-v4.png`。本版取代 v1 的布局与常驻资金口径；v1 仅作为历史方案保留。

## 1. 城市顶部双层一体状态栏

两行共用一个圆角毛玻璃外框，中间只用细分隔线，不留卡片间隙。状态栏不得扩展为经营仪表盘。

### 第一层：经营状态

| 分组 | 常驻内容 | 图标 | 数据要求 |
|------|----------|------|----------|
| 资金 | 当前资金 | 快速月报金色金币 | `funds` |
| 每回合 | 当前状态下预计下一次常态结算的净资金变化 | 已锁定回合收入 B | 新增只读 ViewModel 字段 `recurringFundsDeltaEstimate` |
| 累计 | 已经营月份 | 已锁定日历 A | `currentMonth` 对应的累计月口径 |

`recurringFundsDeltaEstimate` 只包含当前已经生效、能被规则层可靠计算的常态收入与支出；不包含一次性建设扣款、广告奖励、贷款到账、临时事件，以及尚未完成或尚未触发的未来变化。该值必须来自 `sim` / `modules` 的结算真理源，UI 不得自行拼公式。

若预测暂时不可可靠提供，显示 `—` 或隐藏该分组；不得拿最近一次操作 delta、上月实际净现金流或纯收入冒充。建设、事件、奖励与月结结果造成的资金变化仍使用附着于资金分组的短时 `+N / -N` 反馈，与常驻 `+N / 回合` 同时存在时也必须能一眼区分。

### 第二层：供能状态

- 左侧使用已认可的青蓝闪电和短标签“供能”。
- 中间以 `effectiveSupplyMw / demandMw` 驱动进度条，填充比例使用 `supplyRatio`；`effectiveSupplyMw / demandMw MW` 直接写在条内，不在右侧重复数值。
- 超供时填充封顶但保留真实数值；需求为 0 时使用明确定义的空需求状态，不制造除零比例。
- 右侧叶片反映 `cityFullyEcoSupply`：清洁供能为绿色叶片 + 勾；非清洁供能为降饱和叶片 + 斜杠或警示点。状态不能只靠绿色 / 灰色区分。
- 叶片是“当前供能是否完全清洁”的布尔状态，不代表清洁能源占比；若未来需要占比，另行定义数值与图标。
- 供能变化可用短时 `+N MW / -N MW` 解释，但常驻条始终立即刷新为最新有效供能与需求。

## 2. 公司经验栏

- 只在公司页出现，不进入城市顶部状态栏。
- 从左到右固定为：`公司 Lv`、当前等级罗马数字图标、粉紫实体 `EXP` 符号、经验进度条。
- 条内显示 `current / nextThreshold EXP`；不再显示“距升级 N”。
- 当前经验使用底层 `socialValueCurrent`，可随供能与环保结果波动；`companyLevel` 已获得等级不回退。组件附近保留一次简短说明，不在每次变化时重复弹窗。

## 4. 当前实现依赖

- 现有城市 HUD 快照已能提供有效供能、需求、满足率和完全清洁供能状态，可直接支撑第二层。
- `recurringFundsDeltaEstimate` 是新增设计需求；在规则层提供前，原型不得伪造示例值为真实预测。
- 本文只锁定信息架构、视觉语义和数据口径，不授权本轮实现 Cocos。
