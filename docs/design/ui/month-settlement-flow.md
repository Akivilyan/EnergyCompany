# 下一月后的结算反馈流程

> 设计输入：`product-prototype-design-brief.md`、`city-flow-gameplay-contract.md`。本文定义玩家如何理解月结，不把 M1–M14 技术管道直接可视化。
>
> 高保真基准：[`concepts/city-month-event-flow-hifi-v2.png`](./concepts/city-month-event-flow-hifi-v2.png)（普通月结反馈 / 纯 UI 灾害警示）。

## 1. 设计目标

- 高频推月保持一键完成，不增加每月确认框。
- 普通月份在不阻断城市操作的前提下，让玩家看懂资源、项目与供能的主要变化。
- 公司升级、灾害、重大工程与终局使用有上限的阻断反馈队列。
- 所有反馈可追溯：轻提示消失后，资金明细可在公司页查看，灾害可在事件面板查看，在建项目可点场景对象查看。

## 2. 状态流

```text
M0 城市可操作
  └─ 点下一月 → M1 输入锁定 / 结算过渡
                    ├─ 普通月 → M2 轻量月度反馈 → M5 返回城市
                    ├─ 关键节点 → M3 阻断反馈队列 → M4 返回态压力提示 → M5
                    └─ 终局 → M3a 关键因果 → screen_run_result
```

## 3. M1 输入锁定 / 结算过渡

- 点击后按钮立即进入 pressed/loading，月份胶囊显示从“第 N 月”向“第 N+1 月”过渡。
- 场景叠一层约 10%–16% 冰蓝轻遮罩；HUD 保持可见但不可交互。
- 中央只显示三个玩家语义节点：`项目推进 → 供能重算 → 经营结算`。
- 节点按真实完成回调点亮，不为“显得有过程”强制延时；单段淡入或高光 120–220ms。
- 数据立即返回时，整个过渡约 300–450ms；慢设备则停留在当前节点，不循环夸张动画。
- 失败/回滚时不推进月份，遮罩变为稳定错误面板并提供重试；不得先显示资源变化再回滚。

## 4. M2 普通月份轻反馈

### 4.1 三个同步层

1. 顶部资源 capsule：月份切换；资金、SV 显示带正负号的 delta，约 3 秒后收起。
2. 场景对象：在建月份递减；完成设施短脉冲并从脚手架切换为运行态；供能光路按真实结果更新。
3. `MonthReceipt`：资源栏下方出现一条非阻断玻璃速报，只保留本月最重要的 1–2 条事实。

### 4.2 MonthReceipt

```text
┌──────────────────────────────────┐
│ 第3月速报                         │
│ 风电·I 已完工  ·  供能 0% → 3%   │
│ 本月净变化 +38              [明细]│
└──────────────────────────────────┘
```

- 高度约 72–104dp，位于资源栏下方，不覆盖选中地块与 `下一月`。
- 普通月最多两行；显示 3.5–5 秒，可手动关闭。
- `明细`打开公司页最近月度现金流，不再弹第二张月报。
- 若没有项目、供能、等级或事件变化，首行使用“经营稳定”，第二行只显示净资金变化。

### 4.3 内容优先级

同月信息较多时只取靠前两项，其余进入可追溯入口：

1. 资金进入负数 / 连续负资金风险。
2. 设施、线路、研发完成。
3. 供能满足率显著变化或达到 100%。
4. 社会价值跨过或接近升级门槛。
5. 普通净现金流。

## 5. M3 关键反馈队列

### 5.1 非终局

```text
公司升级（若有）
  → 新灾害 / 显著事件（若有）
  → 大型工程完成（若有）
  → 返回城市并合并轻量提示
```

- 同时只显示一张阻断反馈。
- 按钮文案在还有下一张时为“继续”，最后一张为“返回城市”。
- 科技完成、普通设施完成和供能 100% 不进入全屏队列。

### 5.2 终局

- 若新灾害或重大现金冲击直接造成胜负，先展示一张关键因果，再进入结果页。
- 最终灾害通关：最终灾害反馈 → 通关结果。
- 破产：导致负资金的灾害/现金变化摘要 → 破产结果。
- 公司升级与普通完成折叠进结果摘要，避免终局前连续多张“知道了”。

## 6. M4 返回城市后的持续状态

- 新灾害已激活：城市场景保持常态；事件入口显示珊瑚警示三角与未读点，受影响的资金 / 倍率组件使用局部红黄警示。
- 资源栏保留最终数值，不保留永久 delta。
- `MonthReceipt` 的首条改为当前最急迫压力，例如“收入 -8% · 剩 8 月”；同时提供事件面板入口。
- 完工设施保持一次短光晕，玩家首次点选后不再重复脉冲。
- `下一月`恢复可用，但若资金已负，按钮上方出现非阻断“连续负资金 1/2”风险提示。

## 7. 动效与声音

| 反馈 | 动效 | 声音 |
|------|------|------|
| 普通推进 | 月份胶囊轻切换，场景不移动镜头 | 轻短节拍 |
| 正向资金/SV | 数字上跳一次，青绿/粉紫短光 | 清亮音粒 |
| 负向资金 | 数字下移，珊瑚警示形状出现一次 | 低而短的提示音，不做警报循环 |
| 项目完成 | 对象 0.95→1.0 轻缩放 + 核心光 | 温暖完成音 |
| 灾害 | 资金浅珊瑚红警告、倍率浅暖黄警示与事件图标脉冲；场景不变 | 一次短警示音，不增加风雨环境层 |

减少动态模式全部改为淡入与状态直切；UI 不跟随场景震动。

## 8. 数据与交接

- 月结 UI 消费单一 `MonthFeedbackViewModel`，不直接遍历 M1–M14 metrics。
- `projectUpdates` 必须包含项目 ID、类型、progress/completed 与剩余月数，才能把反馈锚回正确场景对象。
- 资金 delta 必须包含灾害即时扣款后的最终结果；展开明细再拆收入、运维、燃料、还贷。
- 阻断队列由业务层排序，UI 不自行推测公司升级与事件优先级。
- 常态反馈可在进入科技/公司/事件页面后提前收起，但不丢失历史明细。

## 9. 原型验收场景

至少走通以下分支：

1. 普通月：无完成、无事件，只显示资源 delta 与稳定经营速报。
2. 建设进度：脚手架剩余月份递减，玩家无需打开队列即可理解。
3. 设施完成：场景对象切换、供能变化、资金变化同时解释。
4. 公司升级 + 灾害同月：先升级、后灾害、返回城市后保留灾害压力。
5. 灾害导致首次负资金：事件影响与“连续负资金 1/2”同时可见。
6. 最终灾害通关 / 灾害导致破产：最多一张因果反馈后进入结果页。
7. 390×844 与 430×932：速报、全屏反馈、资源栏和主按钮无重叠或截断。
