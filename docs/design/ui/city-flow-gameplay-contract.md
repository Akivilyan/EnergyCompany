# 城市关键流程玩法合同

> 用途：城市建设、推月、结算和灾害反馈的玩家可见事实。当前 `PLAYABLE-CORE-01` 只使用建设、月结和供能压力部分；完整灾害留到事件切片。
>
> 快照版本：2026-07-19。规则真理源优先级遵循项目边界：`src/sim/` 当前行为 > 已接线的 `src/modules/` 输出 > GDD / Feature 的目标规则。发现差异时不在视觉稿中擅自补规则，见第 7 节。

## 1. 玩家心智模型

```text
看城市压力
  → 点一个空建设位
  → 选择能解决当前问题的设施
  → 看清本次扣款、工期、产能与长期成本
  → 确认建设
  → 主动推进月份
  → 看懂资金、供能、社会价值、项目与灾害发生了什么
  → 决定下一步建设 / 研发 / 借贷 / 等待
```

玩家不需要理解 M1–M14，也不需要在每月关闭一张固定报表。

## 2. 城市建设合同

### 2.1 入口与前置

- 入口仅在 `screen_city_detail` 的空建设位。
- 当前必须为可操作城市、`run_playable`、非结算中。
- 候选设施来自当前城市与当前科技状态；每条设施线只展示最高可建 tier。
- 当前候选过滤：科技已解锁；水电要求临水；核电要求城市有资格且每城未达 1 座上限。
- 当前客户端能力还要求设施施工队列少于 3，且资金不少于候选建设成本。

### 2.2 候选项必须提供的数据

| 字段 | 玩家文案 | 用途 |
|------|----------|------|
| `facilityId` + `tier` | 风电·I | 识别设施线与等级 |
| `buildCost` | 确认后扣 12 | 确认前的直接经济后果 |
| `buildMonths` | 工期 2 月 | 何时可见结果 |
| `effectiveOutputMw` | 预计补充 42MW | 已包含本地资源与储能倍率的可比较产能 |
| `monthlyOpex` | 每月运维 1 | 长期成本；当前候选 ViewModel 尚未提供，交接前需补合同 |
| `resourceMultiplier` | 本地资源 ×2 | 解释为何同类设施在不同城市价值不同 |
| `storageMultiplier` | 储能增益 ×2 | 仅生效时出现 |

候选列表不显示未解锁 tier 的重复行，不用技术参数淹没首轮选择。

### 2.3 玩家操作与副作用

| 玩家动作 | 系统命令 / 状态 | 玩家可见反馈 |
|----------|-----------------|--------------|
| 点空位 | 仅选择 UI 上下文 | 空位环形光增强；打开建设选择 sheet |
| 点候选设施 | 更新选中候选 | 场景空位出现对应设施的轻量预览；详情区更新 |
| 返回 | 不发命令 | 确认态回选择态；选择态关闭并恢复浏览 |
| 确认建设 | `queue_construction` | 当前运行时一次扣除 `buildCost`；写入施工队列 |
| 成功 | 城市仍可操作 | 顶栏资金显示负向 delta；空位变脚手架/在建；显示剩余月份 |
| 失败 | 状态不变 | 保留玩家选择，显示具体原因与可恢复路径 |

### 2.4 关键异常

| 条件 | 设计处理 |
|------|----------|
| 资金不足 | 主按钮禁用；显示“还差 N”；可提供去公司查看贷款的次操作 |
| 施工队列满 | 显示“在建 3/3”；主按钮替换为“查看在建” |
| 非临水 | 当前实现直接过滤水电；若需教育玩家，在城市标签中解释“无临水条件” |
| 核电未解锁 / 不合选址 | 当前实现直接过滤，不在首轮列表堆锁卡 |
| 结算中 | 不打开 sheet；空位与按钮进入不可交互态 |
| 命令提交失败 | 不关闭 sheet，不扣款；在主按钮上方显示稳定错误条 |

## 4. 下一月与月结合同

### 4.1 入口

- `下一月` 仅常驻城市页，是高频主操作，不做每月二次确认。
- 点击成功后立即锁定输入，进入 `month_settling`；重复点击无效。
- UI 只展示“项目 → 供能 → 经营”三类可理解进度，不展示 M1–M14 技术步骤。

### 4.2 月结后可用事实

| 信息 | 来源 | 玩家用途 |
|------|------|----------|
| 月份 from / to | `SettlementReport` | 确认时间已推进 |
| 资金 before / after / delta | 状态快照 + report metrics | 理解本月盈亏及灾害扣款 |
| 社会价值 before / after / delta | 城市快照 | 理解供能/环保结果 |
| 本地/有效供能与满足率 delta | 城市快照 | 理解设施与电网结果 |
| 收入、运维、燃料、还贷 | M5–M8 metrics | 需要时展开经营明细 |
| 施工、研发、电网队列变化 | 前后状态 + M1–M3 | 场景完成/进度反馈 |
| 公司等级变化 | M10 | 升级反馈与解锁摘要 |
| 新灾害与持续压力 | M11 + Events snapshot | 事件全屏反馈与返回后的压力标记 |
| run result | report result | 通关 / 破产终局 |

### 4.3 反馈强度

| 层级 | 条件 | 反馈 |
|------|------|------|
| 轻量 | 普通月份 | 月份切换；资源 capsule delta；一条非阻断月度速报 |
| 场景内 | 设施/线路/研发完成、满足率 100% | 对应对象短脉冲 + 可追溯提示 |
| 阻断 | 公司升级、新灾害、重大事件/工程 | 全屏反馈队列，一次一张 |
| 终局 | 破产 / 通关 | 关键因果反馈后进入 `screen_run_result` |

常态月份不弹固定经营结果框。详细流水已有公司页最近月度现金流入口；城市页只承担“本月最重要的变化”。

## 5. 灾害合同

### 5.1 当前实现范围

- 当前已接线的是 4 场固定灾害轴；policy / market 随机事件尚不是当前可靠原型输入。
- 触发月：22、41、63、86。
- 预警提前量：8、10、12、14 月。
- 新灾害触发后需要全屏只读确认；玩家不做分支选择。
- 城市事件入口应持续显示即将到来、进行中、已结束；活跃展示上限为 3。
- 灾害只改变数值和局部 UI 状态；城市背景、建筑、地形、天气与全局光照保持常态，不为事件切换场景资产。

### 5.2 全屏事件必须回答

1. 发生了什么：事件名、强度、叙事摘要。
2. 现在损失什么：本月一次性资金影响。
3. 接下来承受什么：确实生效的持续效果与剩余月份。
按钮只确认已读，不伪装成事件选项；统一使用确认 A 对勾。若后面仍有反馈，确认后进入下一张；否则关闭弹层并恢复城市可操作态。

### 5.3 固定灾害数值

| 场次 | 月份 | 即时罚款基准 | 持续 | 收入倍率 | 配置中的建设/研发时长倍率 |
|------|------|--------------|------|----------|---------------------------|
| I | 22 | 6 | 8 月 | 92% | 108% / 108% |
| II | 41 | 3 | 10 月 | 88% | 112% / 112% |
| III | 63 | 22 | 10 月 | 84% | 116% / 116% |
| 最终 | 86 | 48 | 12 月 | 80% | 120% / 120% |

即时罚款还会受难度与风险准备金修正；UI 展示运行时的最终值，不展示玩家不会实际支付的基准值。

## 6. 反馈排队规则

### 非终局月份

```text
结算轻遮罩结束
  → 公司升级（若有）
  → 新灾害 / 显著事件（若有）
  → 大型工程完成（若有）
  → 返回城市，合并展示其余轻量提示
```

### 终局月份

```text
结算轻遮罩结束
  → 与胜负直接相关的新灾害 / 关键因果
  → screen_run_result
```

终局最多保留一张因果反馈再进入结果页；升级、普通完成等折叠进结果摘要，避免连续三四张确认框。

## 7. 已隔离的规则分歧

这些差异已足以影响文案或按钮状态。流程稿使用参数化文案与稳定交互，不替规则层做选择；进入高保真定稿或 Cocos 实现前必须统一。

| 主题 | 当前 `src/sim` | GDD / Feature 目标 | 本轮设计处理 |
|------|----------------|--------------------|--------------|
| 建设扣款 | 一次扣除完整 `buildCost`；不足则拒绝 | 首月分期；允许扣至负数并警告 | 文案写“确认后扣款 N”；按钮能力读取运行时 |
| 全局在建池 | 城建设施队列单独上限 3 | 设施、区域链路、主干共用 3/4 | 组件显示运行时提供的 `active/max`，不硬编码范围 |
| 建设位上限 | dispatch 尚未校验 `build_slot_count` | 在建即占位，位满拒绝 | 原型保留固定空位；实现前补规则校验 |
| 完工生效 | 当前结算中完工后立即进入同月 M4 | 文档写完工次月 M4 生效 | UI 只展示实际 before/after delta，不写死“次月生效” |
| M1–M3 次序 | 当前代码执行 M2 → M3 → M1 | 文档定义 M1 → M2 → M3 | 玩家层合并为“项目推进”，不暴露内部次序 |
| 灾害时长效果 | 收入倍率已参与结算；建设/研发倍率目前只存状态 | 文档要求建设/研发时长倍率生效 | 全屏只展示结算层确认已生效的效果 |
| 事件范围 | 当前可靠接线为固定灾害 | GDD 还定义政策/市场随机事件 | 第一轮高保真只画固定灾害；组件为后续类型留变体 |

## 8. 设计输出需要的最小 ViewModel

为了让正式 UI 不解析底层状态，后续客户端合同至少需要：

```ts
interface BuildChoiceViewModel {
  slotId: string;
  queueActive: number;
  queueMax: number;
  candidates: Array<{
    facilityId: string;
    tier: number;
    buildCost: number;
    buildMonths: number;
    effectiveOutputMw: number;
    monthlyOpex: number;
    resourceMultiplier: number;
    storageMultiplier: number;
    enabled: boolean;
    disabledReasonKey?: string;
  }>;
}

interface MonthFeedbackViewModel {
  monthFrom: number;
  monthTo: number;
  fundsDelta: number;
  socialValueDelta: number;
  supplyRatioBefore: number;
  supplyRatioAfter: number;
  cashflow: { income: number; opex: number; fuel: number; loanPaid: number };
  projectUpdates: Array<{ id: string; kind: string; state: "progress" | "completed"; monthsLeft?: number }>;
  blockingFeedback: Array<{ kind: "level_up" | "event" | "major_complete"; id: string }>;
  result: "continue" | "victory" | "bankrupt";
}
```

这是设计交接所需输出形状，不代表本轮实现 Cocos 或修改模拟规则。
