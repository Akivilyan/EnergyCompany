# 建设流程（城市屏）

> 设计输入：`product-prototype-design-brief.md`、`city-flow-gameplay-contract.md`。本文只定义玩家可见流程、组件状态和交接输出，不重复建设公式。
>
> 高保真基准：[`concepts/city-build-flow-hifi-v1.png`](./concepts/city-build-flow-hifi-v1.png)（选择设施 / 确认建设）。

## 1. 目标与范围

- 父屏：`screen_city_detail`。
- 叠加：`modal_build_list`、`modal_build_confirm`、`panel_construction_queue`。
- 真实操作单位：玩家点一个场景内空位，比较当前可建设施，看清直接与长期后果，确认后立即在该位置看到施工状态。
- 不做：从常驻“建设”入口先开总列表；在同一 sheet 中混入研发、贷款或全公司流水；为锁定科技铺满灰卡。

## 2. 状态流

```text
B0 城市浏览
  └─ 点空位 → B1 选位 / 选择设施
                  ├─ 点候选 → B1a 更新预览与详情
                  ├─ 继续 → B2 确认建设
                  │            ├─ 返回 → B1a
                  │            └─ 确认成功 → B3 已下达 / 场景反馈 → B0
                  └─ 关闭 / 点场景空白 → B0

B1 / B2 任一校验变化
  └─ Bx 阻塞态：资金不足 / 队列满 / 结算中 / 命令失败
```

返回规则：确认态返回选择态并保留候选；选择态返回城市浏览并取消空位选中；任何返回都不产生建设副作用。

## 3. B0 城市浏览态

- 空位以地表轮廓、弱青色环和 `+` 表示；不常驻“建设位”文字。
- 空位可见图形可约 44dp，实际热区至少 56×56dp；与相邻设施热区至少 8dp 间隔。
- 可点击空位只用弱光；`下一月` 暖黄主操作仍是浏览态唯一强焦点。
- 队列已满或结算中时，空位降低光效并叠加小型“暂停/满”形状，不只变灰。

## 4. B1 选位 / 选择设施

### 4.1 场景变化

- 被点空位使用明确环形光，`+` 缩小并上移；其余空位降至静态亮度。
- 选中候选后，空位中心显示该设施的简化投影或色彩轮廓，不使用完整插画冒充已建成设施。
- 场景仍保留约上半屏，玩家始终看得见“建在哪里”。

### 4.2 Bottom sheet

- 390×844：默认高度约 360–390dp；430×932：可增加详情区留白，不放大图标密度。
- 背景为乳白/浅冰蓝稳定玻璃，顶部细高光，浅蓝投影；不实时模糊作为硬依赖。
- 左右内边距 16dp；圆角约 24dp；顶部拖拽条仅表达可收起，不承担关闭功能。

```text
┌──────────────────────────────────┐
│ 在这里建设                 [×]   │
│ 在建 0/3 · 起始城有临水条件       │
│                                  │
│ [风电] [光伏] [火电] [水电]  →   │  候选横向轨道
│   选中环 + 设施名·tier             │
│                                  │
│ 风电·I                  普通资源  │
│ 预计补充 42MW    工期 2月          │
│ 确认后扣 12       每月运维 1       │
│                                  │
│      [ 继续：风电·I ]             │
└──────────────────────────────────┘
```

### 4.3 候选轨道

- 单项热区至少 72×80dp；图标使用设施主色与白描边。
- 初始候选使用运行时选中项；当前起始城默认可选风电、光伏、火电、水电。
- 选中态同时使用 1.05 倍放大、白/青双层选中环与底板变化，不只换颜色。
- 本地资源或储能产生倍率时，在卡片右上放一枚小型 `×2` 光签；详情区用文字解释来源。
- 不展示当前完全不可建的核电；当产品需要解释成长路径时，由科技页承担。

### 4.4 详情优先级

第一眼只比较四项：有效产能、工期、确认后扣款、每月运维。资源倍率是解释标签；内部基础产能、取整和公式不进入首层。

主按钮只表示“进入确认”，不在这里直接提交，避免玩家横滑候选时误建。

## 5. B2 确认建设

- sheet 保持同一容器与相近高度，避免再弹一个居中框。
- 候选轨道收起；场景预览增强，但仍标记为半透明施工投影。
- 标题改为“确认建设 风电·I”，信息集中在三个不可逆后果：资金、队列、等待时间。

```text
┌──────────────────────────────────┐
│ [←] 确认建设：风电·I             │
│                                  │
│ 资金       203  →  191           │
│ 在建队列   0/3  →  1/3           │
│ 可见结果   施工 2 个月             │
│                                  │
│ 完成后预计补充 42MW · 月运维 1     │
│                                  │
│      [ 确认建设 · 扣 12 ]         │
└──────────────────────────────────┘
```

- 金额变化必须同时显示减号/箭头和数字，不只用红色。
- 主按钮高光为暖黄；金额使用深色高对比字，不用白字叠亮黄。
- 不增加“确定吗？”第三层确认。

## 6. B3 成功反馈

确认成功后按以下顺序反馈：

1. 主按钮进入约 150ms pressed/loading，防止重复提交。
2. 顶部资金 capsule 显示 `-12` delta，数字滚动到新值。
3. 选中空位切换为脚手架/地基，出现设施主色轮廓与“2月”进度标记。
4. 队列计数变为 `1/3`；若非浏览所需，不常驻打开队列面板。
5. sheet 在 180–240ms 内收起；底部出现非阻断短提示“风电·I 已开工”。
6. 恢复城市浏览；`下一月`重新成为唯一暖色主操作。

减少动态模式：跳过数字滚动与施工投影缩放，直接切换状态并保留短提示。

## 7. 阻塞与恢复路径

| 状态 | 页面处理 | 主操作 |
|------|----------|--------|
| 资金不足 | 详情保留；资金行显示“还差 N”与警示三角 | 禁用“确认建设”；次操作“去公司”仅在贷款可用时出现 |
| 在建 3/3 | 候选仍可浏览，不允许进入提交 | “查看在建”打开 `panel_construction_queue` |
| 结算开始 | 关闭未提交确认并保存上次候选；场景输入锁定 | 无 |
| 命令失败 | sheet 不关闭；按钮上方稳定错误条，避免只闪 Toast | “重试”或按错误原因替换 |
| 无候选 | 显示城市条件摘要，不画空白列表 | “查看科技”仅在科技页已解锁时出现 |

## 8. 在建状态与队列入口

- 在建地块本身就是主要入口：点击显示项目名、剩余月份与取消入口。
- 多城/多项目总览才使用 `panel_construction_queue`；不在城市底部常驻一个大队列卡。
- 取消属于风险操作，必须二次确认并明确退款结果；不与本轮新建主流程并列。

## 9. 实现交接

- `modal_build_list` 与 `modal_build_confirm` 共享一个 `BottomContextSheet`，通过状态变体切换，不创建两套视觉组件。
- 场景空位需要稳定 `slotId`，即使当前模拟命令仍以 `cityId` 为主。
- 候选 ViewModel 需补 `monthlyOpex`、`enabled` 与 `disabledReasonKey`；完整字段见 `city-flow-gameplay-contract.md`。
- 视觉稿的“资金 203→191”是起始城风电·I 的真实样例；正式组件全部数据驱动。

## 10. 原型验收

- 玩家能在 3 次明确点击内完成：空位 → 风电 → 确认。
- 确认前能同时看见位置、扣款、工期、有效产能和月运维。
- 成功后不看文字也能从资金变化、脚手架和月份标记理解“已扣款、未完工”。
- 资金不足、队列满与返回路径均不会误提交或丢失原因。
- 390×844 与 430×932 中，sheet 不遮住选中空位；所有主热区 ≥48dp，无文字截断。
