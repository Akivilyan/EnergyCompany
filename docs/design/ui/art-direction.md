# UI 美术与音频方向

本文定义当前 demo 的视觉与音乐基调，作为正式 UI / Prefab 批次、场景资产、图标和反馈动效的共同依据。具体屏幕结构仍以 `docs/design/ui/` 各屏幕文档为准。

## 1. 总体基调

项目主基调为：明亮、自然、未来感、希望感。

目标观感：

- 明亮卡通新能源群岛
- 轻科幻城市经营
- 柔和发光电网
- 清洁能源与自然环境共存
- 城市由压力状态走向可治理、可恢复、可升级

画面未来可以扩展夜景、季节和低清洁度反馈，但 `PRODUCT-PROTOTYPE-01` 不为灾害制作雨雪、洪水、雾霾或其它整场景变体。灾害在当前阶段只改变数值与局部 HUD 警示，不改变城市背景、建筑、地形、天气或全局色调。

## 2. 核心设计参考与借鉴边界

产品原型与正式 UI 必须同时保留以下两个核心参考，但只借鉴其适合本项目的结构与体验，不复制题材、美术皮肤或完整系统。

| 参考 | 主要借鉴 | 在本项目中的落点 | 明确不借鉴 |
|------|----------|------------------|------------|
| 《三国志12》 | 战略地图到城市的空间层级、地图节点关系、城内固定建设位与点空位建设 | `screen_world_map` → `screen_region` → `screen_city_detail`；城市中的已建设施、空位、在建/运行状态和设施详情 | 武将、兵团、战争系统；桌面端高密度操作；原作题材与美术皮肤 |
| 《大理石时代》 | 清晰的经营快照、近月流水、事件造成的阶段压力、固定大考与提前预警、失败后重开的经营节奏 | `screen_company` 的经营摘要；事件/灾害时间轴；建设、研发、现金流之间的备考取舍 | 城市主界面与建设位画面布局；单根多层交叉科技树；古典石质视觉风格 |

组合原则：以《三国志12》提供“世界—区域—城市—建设位”的空间结构，以《大理石时代》提供“经营—预警—备考—承压—恢复”的时间节奏，再统一转换为本项目的竖屏微信小游戏交互与明亮新能源视觉语言。

## 3. 禁止项

以下方向不作为本项目默认风格：

- 暗黑中世纪、地穴、废墟求生、末世废土
- 大面积黑灰褐、脏污纹理、恐怖剪影、阴森雾气
- 强压迫、绝望、不可恢复的灾难氛围
- 像素化主视觉
- 重金属、厚边框、魔幻卷轴式 UI

允许深色和夜景，但禁止压抑暗黑调性。夜景应呈现城市灯带、电网光路、水面反光、设施光晕和远景层次。

## 4. 视觉语言

### 4.1 形状与线条

- 非像素化卡通风
- 简单、干净、可识别的线条勾勒
- 建筑使用圆润、色块明确的未来工业体；白色只承担提亮与连接作用，不作为所有设施的统一底色。不同能源设施必须有可记忆的主色身份
- UI 使用白色 / 浅冰蓝软卡片、较大圆角、轻阴影和克制的半透明高光；避免深蓝厚底、硬边框和旧式工具栏
- 建筑和 UI 边角偏圆润，但不过度糖果化
- 设施轮廓优先服务识别：风电、光伏、水电、核电、储能、电网节点应一眼可分

### 4.2 色彩

- 主色：天空蓝、湖蓝、薄荷绿、暖黄
- 辅色：白色、浅灰蓝、草绿、清透青色
- 风险色：珊瑚橙、暖红，仅用于提示和临时压力状态
- 高阶科技色：蓝紫或青紫，仅作点缀，不大面积铺底

画面默认保持清透、高明度和较丰富但受控的饱和度。使用“环境蓝 + 设施主色 + 白色高光 + 深色结构”的配色关系形成层次，避免整座城市被洗成浅蓝白。当前阶段的负面经营状态不对整座城市降饱和或加灰雾，只通过局部数值、图标和玻璃承载层表达。

#### 4.2.1 设施色彩身份

色彩首先帮助玩家识别设施类别，其次才承担装饰。每类设施控制在 2—3 个主体颜色，远看有明确色块，近看再补充材质和能源光。

| 设施类型 | 主体配色 | 识别意图 |
|----------|----------|----------|
| 风电 | 天空蓝、白、少量暖黄 | 清洁、轻盈、与天空呼应 |
| 光伏 | 深钴蓝、青色框架、少量黄绿指示 | 平整、阵列化、高科技 |
| 水电 / 电网 | 湖蓝、青绿、亮黄 | 流动、连接、稳定输送 |
| 火电 | 浅珊瑚红、杏橙、浅蓝灰结构 | 高热、高输出、工业力量；保持明亮整洁，不做砖红、褐黑或脏污废土 |
| 核电 | 明亮琥珀橙、奶油白、少量蓝灰 | 高阶、稳定、体量感；避免危险符号堆砌和深色大块面 |
| 储能 | 薰衣草紫、兰花紫、天空青能源带 | 模块化、能量储存、与发电设施区分 |
| 通用建筑 | 米白、蓝灰，按功能加入一处高饱和强调色 | 作为场景缓冲，不争夺能源设施焦点 |

红橙不只作为警告色使用。设施本体可以长期使用红橙主色，但风险状态必须再叠加警示图形、闪烁节奏或文字，不能仅靠颜色表达。

### 4.3 光效

光效用于表达状态，而不是通用装饰。

- 可操作节点：轻微外发光
- 已接通电网：稳定蓝青光路
- 建设完成 / 升级完成：短时增强光晕
- 高价值设施：柔和核心光
- 受灾 / 低清洁度：光效减弱或闪烁，但不长期刺眼

常驻界面应控制发光密度，避免背景抢 HUD 信息。

#### 4.3.1 日照与阴影

默认城市画面采用高明度正午日照和充足天空补光，目标是“阳光明媚、清爽通透”，不使用强调体积压迫感的戏剧化重阴影。

- 建筑投影使用短距离、低透明、软边浅蓝灰，不使用纯黑或大面积炭灰。
- 环境光遮蔽只保留在设施接地、结构交界等很小的接触区域，不把整面背光立面压暗。
- 背光面必须获得天空、水面和浅色地面的环境反射光，保持材质颜色可辨。
- 高饱和颜色集中在设施识别面和交互焦点；大面积侧面使用更高明度的同色浅阶。
- 深色机械结构只作小面积点缀，不能形成连续暗块；树木与岩石同样避免压黑。
- 允许轻微远景空气透视，但不能用灰雾降低阳光感，也不能用过曝抹掉建筑轮廓。

### 4.4 图标语言

- 统一使用高饱和彩色实体符号、清晰白色外描边、圆润几何轮廓和轻微同色投影；通过一致的体积、描边和光影形成家族感，而不是把所有图标染成同一种蓝色。
- 图标正下方增加很短的同色柔光倒影：约 15%—25% 不透明度、小幅垂直偏移和柔和模糊；它只增强悬浮与通透质感，不形成完整镜像，也不替代触控反馈。
- 图标本体可加一条克制的白色高光边，但禁止厚重黑投影、塑料浮雕或大面积外发光。
- 图标按语义分配主色：资金为金黄，SV 为粉紫，月份为靛紫，地图为薄荷绿，公司为紫色，建设为橙色，电力为青色或黄色，风险为珊瑚红。
- 单个图标应优先依靠自身轮廓从场景中分离，不强制套入相同的白色圆形容器；触控热区可以大于可见图形。
- 图标先表达功能，再表达题材；地图、研发、公司、建设等入口在缩小后仍应一眼可分，内部细节保持克制。
- 激活态必须同时使用放大、描边/光晕、底板或形状变化，不能只依赖颜色。
- 禁止硬方角、厚重工业模板、徽章化、军政符号化和带年代感的拟物浮雕。
- 第一轮方向稿见 [`concepts/product-prototype-direction-v2.png`](./concepts/product-prototype-direction-v2.png)；它只保留色彩、建筑与圆润图标方向，其常驻卡片、底部导航和信息铺陈方式已废弃，不作为场景页结构参考。

### 4.5 场景优先与 HUD 克制

城市、区域和世界地图采用“场景即主界面”的游戏交互，而不是把经营数据持续铺成移动端 App 仪表盘。

- 默认浏览态应把绝大部分屏幕留给可观察、可点按的场景；常驻 HUD 只保留资金、SV、月份、关键预警和极少数高频入口。
- 不在场景页常驻底部标签导航、大块经营卡片、图表、建筑名称牌或设施详情；公司、科技等独立管理页可以使用完整面板。
- 设施、空建设位、城市节点和事件均先在场景中表达可点状态；玩家点选后，才出现与当前对象有关的名称、数值和操作。
- 上下文信息优先使用紧凑底部浮层、锚定气泡或局部抽屉；打开后仍需保留足够场景，关闭后恢复干净浏览态。
- 空位使用地表轮廓、柔和光环和加号表达，不为每个空位常驻文字标签；未选中的设施不悬浮信息卡。
- 主操作必须克制且稳定：同一时刻只突出一个主要动作，其余入口退居屏幕边缘，不与场景争夺注意力。
- 触控区仍需约 48×48dp 以上；“减少按钮”不等于缩小按钮或隐藏必要状态。

### 4.6 半透明玻璃与光晕层级

HUD、按钮和上下文浮层采用轻盈的半透明玻璃材质：通过背景透色、柔和渐变、明亮边缘高光和浅色投影建立空间层次。借鉴现代消费电子界面的通透感与精确排版，但不复制具体品牌组件，也不让产品变成系统 App。

- 玻璃只用于资源胶囊、主要按钮、上下文浮层和少量临时反馈；场景建筑、固定地块和大面积页面背景不玻璃化。
- 玻璃面板必须有稳定的乳白或浅冰蓝承载层，动态背景不能直接穿透到影响文字和图标可读性。
- 边缘高光应细、亮、连续；投影使用浅蓝或同色柔光，禁止黑灰厚阴影和明显塑料浮雕。
- 同一组件内部最多使用一层主玻璃面和一层交互高光，避免多重透明描边造成廉价霓虹感。
- 光晕按交互层级分配：静态信息只保留边缘高光；可点击对象使用弱光；当前选中对象使用明确环形光；主操作使用暖色高光；风险和完成反馈才允许短时脉冲。
- 空建设位、选中建筑、主按钮和手机安全边框不能长期以同等强度发光，视觉焦点必须随玩家当前操作切换。
- Cocos 实现优先使用预制渐变、九宫格面板、边缘贴图和局部光效模拟玻璃；不把实时背景模糊作为低端设备上的强制依赖。

城市页交互结构见 [`concepts/city-scene-first-states-v1.png`](./concepts/city-scene-first-states-v1.png)，设施色彩身份见 [`concepts/city-scene-first-color-system-v2.png`](./concepts/city-scene-first-color-system-v2.png)，高明度日照与轻阴影见 [`concepts/city-scene-first-lighting-system-v3.png`](./concepts/city-scene-first-lighting-system-v3.png)，半透明玻璃与光晕整合见 [`concepts/city-scene-first-glass-direction-v4.png`](./concepts/city-scene-first-glass-direction-v4.png)。v4 是当前视觉方向基准。

## 5. 场景状态

### 5.1 昼夜

昼夜变化用于降低视觉疲劳，并强化能源网络的存在感。

| 状态 | 视觉目标 |
|------|----------|
| 白天 | 清晰经营视图，蓝天、绿地、水面和设施轮廓明确 |
| 黄昏 | 暖色奖励感，适合建设完成、阶段推进和城市升级 |
| 夜间 | 明亮未来夜景，灯带、电网、反光和远景层次丰富 |

夜间不是暗黑风。夜间画面应让玩家感到城市仍在运转，而不是陷入危险或绝望。

### 5.2 四季

四季用于丰富城市差异和长期经营观感。

| 季节 | 视觉目标 |
|------|----------|
| 春 | 嫩绿、花树、清亮水面 |
| 夏 | 蓝天、强日照、饱和海岸 |
| 秋 | 金黄树冠、暖色夕阳 |
| 冬 | 浅雪、冰蓝高光、暖窗灯 |

四季变化不得影响核心可读性：建筑、地块、电网线和按钮状态仍需清楚。

### 5.3 清洁度与污染

清洁度不足时允许画面短时变压抑，但必须服务状态反馈。

| 状态 | 表现 |
|------|------|
| 清洁 | 天空清透，水面明亮，植被饱和，电网光路稳定 |
| 偏低 | 远景轻灰雾，饱和度略降，建筑高光变弱 |
| 高污染 | 局部烟霾、天空偏灰、工业区域蒙灰，治理提示增强 |
| 恢复 | 雾霾散开，光路回稳，水面和植被颜色回暖 |

污染反馈应让玩家看见问题，也看见治理方向。

### 5.4 灾害

当前阶段不制作灾害场景变体。无论台风、热浪、洪水或寒潮，城市继续使用同一套正常场景资产与光照；不增加雨雪粒子、水位变化、树木动画、全局罩色、雾霾、设施受灾贴图或灾后恢复场景。

灾害只通过局部 UI 表达：

- 资金 capsule：短时浅珊瑚红底、警示三角与负数 delta。
- 收入 / 运维等持续倍率：浅暖黄警示卡、对应图标、数值和剩余月份。
- 事件入口：未读脉冲与 active 剩余月数。
- 全屏反馈：沿用正常城市背景，在稳定玻璃信息层上展示即时与持续数值影响。

这一约束避免形成“城市 × 灾害 × 季节 / 昼夜”的资产乘法。未来若玩法验证证明场景反馈有明确收益，再作为独立美术批次评估，不作为当前原型或首轮 Cocos 的前置条件。

## 6. 资产拆分原则

正式 UI 资产应从概念图拆成可复用层，而不是直接使用整张插画。

- 背景层：地形、海岸、天空、远景城市
- 建筑层：风电、光伏、水电、火电、核电、储能、总部、电网节点
- 电网层：线路、节点、接通状态、断开状态
- 光效层：可建、在建、已接通、升级完成；灾害不增加场景光效资产
- UI 层：面板、资源栏、按钮、标签、弹窗、结果页
- 图标层：现金、社会价值、负荷、供能、清洁度、科技、灾害、贷款、广告

第一批正式化优先验证城市页：城市背景、克制资源栏、场景内建设位、点选反馈、上下文详情浮层、电网/建筑发光状态和一个灾害或建设完成反馈。

## 7. 音频方向

音乐主基调与视觉一致：明亮、舒展、自然、未来、希望。

| 场景 | 音频目标 |
|------|----------|
| 常态经营 | 轻电子、木质或自然音色，节奏稳定，不压迫 |
| 城市建设中 | 轻快节奏、拨奏、柔和合成器，表现忙碌但不焦虑 |
| 科技升级 / 电网完成 | 清亮音粒、上行旋律、温暖完成音效 |
| 清洁度偏低 | 低频略重，旋律减少，环境音变闷 |
| 灾害期间 | 一次短警示音与数值反馈音；不增加风雨环境层或长期循环警报 |
| 灾后恢复 | 局部警示解除音；场景与常态音乐不需要切换 |
| 终局完成 | 开阔、明亮、宽广合成器或合唱感，不做史诗压迫 |

负面音频同样只作为状态反馈，不成为长期底色。

## 8. 下一步样张要求

下一张 UI 样张应是实际可玩界面，不是宣传海报或静态经营仪表盘。

必须包含：

- 同一城市的默认浏览态与点选对象态
- 默认态以城市页背景为主体，只保留克制资源栏、关键预警、一个主操作与少量边缘入口
- 至少 3 类可在场景中直接辨认的能源设施
- 固定建设位的可点状态，以及设施或建设位被点选后的上下文浮层
- 电网接通 / 未接通状态
- 1 个临时状态反馈：低清洁度、灾害预警或建设完成

默认态与点选态通过后，再扩展区域、世界地图、公司和科技页面；完整产品原型评审通过后，才进入正式 UI / Prefab 拆分与 Cocos 落地。
