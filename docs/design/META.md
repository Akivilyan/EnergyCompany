# 设计文档规范

本文档定义 `docs/design/` 的长期写作约束，只保留仍然有效的格式与分层规则。

## 1. 命名与语言

| 类型 | 路径 | 规则 |
|------|------|------|
| GDD | `gdd/` | `NN-topic.md` |
| Feature | `features/` | `topic.md` |
| UI | `ui/` | 与 Feature 同名优先，总览用 `00-` |
| Data | `data/` | 表名或 `schemas/*.md` |
| Engineering | `engineering/` | `kebab-case.md` |

- 正文使用简体中文
- `id`、字段名、枚举值使用英文
- 文件名全小写，单词用 `-`

## 2. Front Matter

所有新建设计文档都应带 YAML front matter：

```yaml
---
id: gdd/00-vision
title: 愿景与边界
status: draft
version: 0.1.0
sources: []
supersedes: []
depends_on: []
open_questions: []
---
```

状态含义：

| 值 | 含义 |
|----|------|
| `draft` | 仍在修订 |
| `locked` | 已确认，可作为下游依据 |

## 3. 分层职责

### GDD

- 只写规则、流程、边界、公式
- 不写引擎 API
- 不写组件树或像素级 UI

### Feature

- 写输入、输出、行为、副作用、验收
- 规则细节引用 GDD，不整段复制

### UI

- 写屏幕结构、组件树、交互、状态
- 不重复完整规则说明

### Data

- 写配置结构、字段、样例与校验要求

### Engineering

- 写架构边界、实现拆条、联调路径、当前阶段状态

## 4. 交叉引用

- 仓库内文档用相对路径链接
- 引用规则时优先链到对应章节锚点
- 同一规则只在最适合的层级写完整版本

## 5. 设计参考

- 大地图与城市建设界面参考《三国志12》的结构感
- 科技树 UI 参考《帝国时代2》式分页平铺
- 这些参考只用于取舍方向，不要求机制一一映射

## 6. 数值原则

- 存档与结算优先整数
- 配置可写百分比或固定整数 modifier
- 百分比与乘区计算结果默认取整
