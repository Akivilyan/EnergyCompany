# 重玩性、经营方针与胜负

## 概述

本章定义 **单局可重玩** 的结构：**经营方针（doctrine）× 难度 × 局外方针等级 × 灾害战役通关/破产失败**，并约定与 **整数数值** 原则的衔接。

**取代**「单线扩张、无终点、无路线差异」的隐性假设；**不**引入成就系统或竞争公司。

**术语区分**（避免与 [03-social-value.md](./03-social-value.md) 混淆）：

| 术语 | 含义 |
|------|------|
| **公司等级 I–V** | 单局内随社会价值升档，解锁区域与科技 **解锁** |
| **经营方针** | 新游戏时选择的 **路线**（风光 / 水电 / 化石 / 科技） |
| **方针局外等级 1–5** | 跨局存档，同方针多次通关累积；只加强 **方针特色** |
| **游戏难度** | 本局 `simple` / `normal`，影响灾害与容错 |

---

## 设计可行性审视（2026-05-24）

| 维度 | 结论 | 说明 |
|------|------|------|
| **四方针 + 统一 lit 预算** | **可行** | **`doctrine_lit_budget = 15`**；主线与 `eng_*` **同一池、玩家自由分配** |
| **灾害战役通关** | **可行** | 与 [08-events.md](./08-events.md) 灾害考试一致；需 **配置表驱动** 10+ 场序列表，与 company_level **解耦** |
| **连续 2 月负债破产** | **可行** | 月度管道末检视；任意月回正即清零，与贷款/退款/取消研发兼容 |
| **整数数值** | **可行，须全表贯彻** | 配置 **可写百分比**；**结算时舍弃小数、只保留整数**（见「整数数值原则」） |
| **定式风险** | **可控但需 playtest** | 固定值可算最优解；靠 **方针互斥 lit 预算**、**灾害序列**、**地理差异** 拉开局间差异；数值表须 **多方针分别验算**（T37） |

**首版 v0 可裁剪**：仅 **1 方针 + 简单难度 + 局外 L1**；字段 `doctrine_id` / `difficulty` / `doctrine_meta_level` **必须预留**。

## 新游戏流程

```text
主菜单 / 继续
  → 新游戏
      ① 选择经营方针（4 选 1）
      ② 选择难度（简单 / 一般）
      ③ 展示本局 modifier 摘要（方针特色 + 局外等级 + 难度）
  → 进入 I 级单城（见 05-map-and-slots 起始城配置）
  → 单局进行 …
  → 通关（撑过最终灾害）或 破产失败
  → 结算：方针局外等级 +1（简单）或 +2（一般），写入存档
```

**继续游戏**：恢复 `doctrine_id`、`difficulty`、本局进度；**不可**中途改方针或难度。

## 游戏难度

首版 **仅两档**：

| 难度 ID | 显示名 | 设计意图 |
|---------|--------|----------|
| `simple` | 简单 | 更高起始资金、灾害负向 **固定值** 下调、破产前容错 |
| `normal` | 一般 | 基准表；**能运营多久看天意**（事件与灾害 RNG + 玩家决策） |

**不调**核心规则（临水建水电、lit 预算、2 月破产等两档相同）。

难度 **固定偏移** 进 `difficulty_modifiers` 表（整数，T37），示例方向：

| 字段 | 简单 | 一般 |
|------|------|------|
| `starting_funds_bonus` | +大 | 0 |
| `disaster_cash_penalty_offset` | 负向 `one_time_cash` 绝对值减小 | 0 |
| `campaign_disaster_intensity_offset` | −1 档（不低于 1） | 0 |

## 经营方针（四类）

### 总表

| ID | 显示名（占位） | 局内核心特色 | lit 预算 |
|----|----------------|--------------|----------|
| `renewable` | 风光电 | 开局 **储能系统 + 储能·I** 已点亮；风光建设 **固定减免** | **受限**（= `doctrine_lit_budget`） |
| `hydro` | 水电 | **临水** 规则不变；常规+超级水电 **额外供能乘区** | **受限** |
| `thermal` | 化石能源 | 火/核 **月运维 = 0**；开局 **清洁煤电 + 无害化核废料** 已点亮 | **受限** |
| `tech` | 科技 | 研发 **固定费/固定工期** 减免 | **无上限**（唯一可满科技） |

### 1. 风光电 `renewable`

储能 **·I～·III**（`storage_1～3`）与风光 **·III～·V** 配套；方针须保证 **三条储能线都能点亮**，但不一次性全送。

| 项 | 规则 |
|----|------|
| 开局点亮（不占 lit 预算） | `storage_system`（出力 ×2、拉平波动）+ **`storage_1`（储能·I）**；**不**送 `storage_2`、`storage_3` |
| 建设 | 风光设施 `build_cost` **−固定值**、`build_duration` **−固定月数**（叠加局外等级） |
| lit 目标（须用满 **14** 点） | `wind_2～5` + `solar_2～5` + **`storage_2`、`storage_3`** + 电网核心 + `super_hydro` |
| 异线 | **火/核/常规水电** 仅 ·I（开局已 lit）；**不可研 ·II 及以上** |

### 2. 水电 `hydro`

| 项 | 规则 |
|----|------|
| 地图 | **仅** `has_river = true`（**临水**）可建常规水电；**不**放宽选址 |
| 供能 | 常规水电、超级水电各乘 **`doctrine_hydro_mult`**（整数比，如 ×150/100；见 [04-energy-supply.md](./04-energy-supply.md)） |
| lit 目标 | 保障 `hydro_2～5` + 电网核心 + `super_hydro`；风光火核 **不可升 tier** |

### 3. 化石能源 `thermal`

| 项 | 规则 |
|----|------|
| 开局点亮 | `eco_thermal`、`eco_nuclear` |
| 运维 | 火、核设施 **`monthly_operating_cost = 0`**（仍计建设费、研发费；事件可临时加价） |
| lit 目标 | 保障 `thermal_2～5` + `nuclear_1～3` + 电网核心 + `super_hydro`；风光水 **不可升 tier** |

### 4. 科技 `tech`

| 项 | 规则 |
|----|------|
| lit 上限 | **无**；唯一可点亮 **全部** 可研节点（含经营减压） |
| 建设/运维 | **无** 方针级优势（或仅极弱，待表） |
| 研发 | `research_cost` **−固定值**、`research_months` **−固定月数**（叠加局外等级） |

## 科技点亮预算（非科技方针）

### 统一池 · 自由分配

非科技三方针（风光 / 水电 / 化石）共用 **`doctrine_lit_budget = 15`**（单局 lifetime 总点亮次数）。

| 规则 | 说明 |
|------|------|
| 计数 | 任意可研节点 `researching → lit` 均占用 **1** 点（**不分** 主线 / 经营） |
| 不计入 | 全局开局 ·I；风光方针额外开局 `storage_system`、`storage_1` |
| 玩家选择 | 在 **异线硬顶** 与 **公司等级 / 前置** 约束下，**自由** 组合主线节点与 `eng_*` |
| **`tech` 方针** | 预算 **不生效**（∞） |

**上限推导**：风光满线 **最少 14** 点（见下表）+ **1** 点灵活位（可点 `eng_green_pr` 等，或换取舍）→ **15**。

### 风光满线参考（14 点，非强制）

**开局已 lit（0 点）**：`wind_1`、`solar_1`、`storage_system`、`storage_1`

**若要点满风光典型终局**（占 14 点）：

| 节点 | 数量 |
|------|------|
| `wind_2`～`wind_5` | 4 |
| `solar_2`～`solar_5` | 4 |
| `storage_2`、`storage_3` | 2 |
| `grid_regional`、`grid_backbone`、`uhv_transmission` | 3 |
| `super_hydro` | 1 |
| **小计** | **14** |

**第 15 点** 示例（自由选，非唯一解）：

| 取舍示例 | 说明 |
|----------|------|
| **满线 + `eng_green_pr`** | 14 + 1；风光全环保时 SV 加成最顺 |
| **满线 + `eng_risk_reserve`** | 偏灾害战役生存 |
| **省 1 主线 + 2 个 `eng_*`** | 如不做 `super_hydro`，换施工/集采等（仅 15 点内） |

水电 / 化石 **同一 15 点池**：本线 + 电网 + 超水电 + 若干 `eng_*` 由玩家自行搭配；异线仍 **不可升过 ·I**。

### 异线 tier 硬顶

非科技方针、非 `tech` 方针时，下列节点 **永久不可研**（`locked`，非灰显可点）：

| 方针 | 硬顶 |
|------|------|
| `renewable` | `thermal_*`、`hydro_*`、`nuclear_*` 仅 **·I**（已 lit）；不可研 ·II 及以上 |
| `hydro` | `wind_*`、`solar_*`、`thermal_*`、`nuclear_*` 仅 ·I |
| `thermal` | `wind_*`、`solar_*`、`hydro_*` 仅 ·I |

电网核心、`super_hydro`、本线 ·II～V、本线相关 ECO（化石局已开局点亮）**不受** 此硬顶。

### UI

科技树显示（非 `tech` 方针）：**「本局剩余点亮：N / 15」**（`tech` 方针：**无上限**）。

## 方针局外等级（1～5）

每条方针 **独立** 存档 `doctrine_meta_level`（1～5）。

| 通关难度 | 升级 |
|----------|------|
| `simple` | 该方针 **+1**（上限 5） |
| `normal` | 该方针 **+2**（上限 5） |

**数值保守、固定值为主**（进 `doctrine_meta_table`，T37）。示例 **形状**（非最终数）：

| 等级 | 风光：建设费 | 风光：工期 | 水电：供能 mult 分子 | 化石：火核运维 | 科技：研发费 |
|------|--------------|------------|----------------------|----------------|--------------|
| L1 | −50 | 0 | +10（×110/100） | 已为 0 | −50 |
| L2 | −100 | 0 | +20 | — | −100 |
| L3 | −150 | −1 月 | +30 | — | −150 |
| L4 | −200 | −1 月 | +40 | — | −200 |
| L5 | −250 | **−1 月**（再叠） | +50（×150/100） | — | −250 |

说明：

- 表中「−50」等为 **固定货币单位**（与 `funds` 同单位），**不是** 10% 类浮点比例。
- L5 风光 **工期再 −1 月** 为方针 **封顶福利** 示例；是否叠 L3 同项由表定。
- 各级 **只加强本方针列**，避免五级后 universal 碾压。

## 胜负条件

### 失败：破产

见 [02-economy.md](./02-economy.md#破产)：

- 连续 **2** 个自然月、月度管道 **全部结算完成后** `funds < 0` → **本局失败**。
- 任意一个月末 `funds ≥ 0` → 连续计数 **清零**（贷款、退款、收入、事件补贴等 **任何** 合法手段回正均算）。

### 胜利：灾害战役通关

借鉴《大理石时代》：

```text
单局配置 campaign_disasters[]（≥10 场，表驱动）
  → 按 schedule 触发 disaster 类事件（全屏弹窗 + 考试强度）
  → 新手常在第 3～4 场前后因破产出局
  → 撑过列表中「最终灾害」且当月末未破产 → 本局通关
```

| 项 | 规则 |
|----|------|
| 与 company_level | **无硬性绑定**；可 V 级前通关，也可 V 级后仍须撑完灾害 |
| 与 policy/market | 战役外仍可有常规事件；**同时 active ≤ 3** 不变 |
| 通关奖励 | 方针局外等级 +1 / +2；可展示 **本局摘要**（存活月数、经历灾害场数、最终资金） |

战役表字段（`data/campaign_disasters`，T37）：`sequence_index`、`trigger_month` 或 `trigger_after_disaster_index`、`event_id`、`is_final`。

## 整数数值原则（全项目）

与 [META.md §12](../META.md#12-数值原则整数优先) 一致。

### 核心规则

| 项 | 规则 |
|----|------|
| **存档与顶栏** | `funds`、供能 MW、工期月数等 **一律整数** |
| **配置表** | **可写百分比**（如 `build_cost_mult_pct = 85` 表示 85%）或 **固定加减** |
| **结算** | 凡经百分比/乘除得到的金额或 MW，**舍弃小数、只保留整数部分**（`floor`  toward 0；实现：`result = (base * num) // den`） |
| **示例** | 造价 1000、85% → `(1000 * 85) // 100 = 850`；**不** 存 850.0 浮点 |

百分比 **更容易配表**（策划写 85、115）；**运行时绝不保留小数**，避免定式 exploit 与累误差。

### 结算顺序（T22 实现）

```text
base（整数）
  → ± doctrine / event 固定值
  → × 百分比或 mult_num/mult_den（整数演算）
  → // 或 floor 得最终整数
  → 扣款 / 写入存档
```

**供能乘区**仍优先 ×2、×150/100 等 **整数比**；结果 **向下取整** 到 MW 整数。

Playtest 须 **分方针、分难度** 跑通战役表，避免单一建设顺序通吃。
