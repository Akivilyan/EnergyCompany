# 重玩性、经营方针与胜负

## 概述

本章定义 **单局可重玩** 的结构：**经营方针（doctrine）× 难度 × 局外方针等级 × 灾害战役通关/破产失败**，并约定与 **整数数值** 原则的衔接。

**取代**「单线扩张、无终点、无路线差异」的隐性假设；**不**引入成就系统或竞争公司。

**术语区分**（避免与 [03-social-value.md](./03-social-value.md) 混淆）：

| 术语 | 含义 |
|------|------|
| **公司等级 I–V** | 单局内随社会价值升档，解锁区域与科技 **解锁** |
| **经营方针** | 新游戏时选择的 **路线**（风光 / 水电 / 化石 / 科技） |
| **方针熟练度 1–3** | 跨局存档，同方针多次通关累积；只 **小幅** 加强方针特色 |
| **游戏难度** | 本局 `simple` / `normal`，影响灾害与容错 |

---

## 设计可行性审视（2026-05-24）

| 维度 | 结论 | 说明 |
|------|------|------|
| **四方针 + 统一 lit 预算** | **可行** | **`doctrine_lit_budget = 15`**；主线与 `eng_*` **同一池、玩家自由分配** |
| **固定灾害通关轴** | **可行** | 与 08 一致；**4 场**、**12 月预警**；**通关月 ≈ 84**（非日历硬顶）；与 company_level **解耦** |
| **连续 2 月负债破产** | **可行** | 月度管道末检视；任意月回正即清零，与贷款/退款/取消研发兼容 |
| **整数数值** | **可行，须全表贯彻** | 配置 **可写百分比**；**结算时舍弃小数、只保留整数**（见「整数数值原则」） |
| **定式风险** | **可控但需 playtest** | 固定值可算最优解；靠 **方针互斥 lit 预算**、**灾害序列**、**地理差异** 拉开局间差异；数值表须 **多方针分别验算**（T37） |

**Playable v0（内测垂直切片）**：仅 **`tech` 方针 + `simple` 难度**；新游戏 UI 可只暴露这两项（其它选项实现层保留、不展示即可）。字段 `doctrine_id` / `difficulty` / 局外成长 **必须预留**。

## 新游戏流程

```text
主菜单 / 继续
  → 新游戏
      ① 选择难度（简单 / 一般）
      ② 方针屏：**教学**（教程关卡，见 [10-onboarding.md](./10-onboarding.md)）或 **四方针** 选一
      ③ 若正式局：展示 modifier 摘要（方针特色 + 局外等级 + 难度）
  → 进入 I 级单城（见 05-map-and-slots 起始城配置）
  → 单局进行 …
  → 通关（撑过最终灾害）或 破产失败
  → 结算：该路线 **熟练度 +1**（简单）或 **+2**（一般），上限 **3**，写入存档
```

**继续游戏**：恢复 `doctrine_id`、`difficulty`、本局进度；**不可**中途改方针或难度。

## 单局时长（定稿）

| 概念 | 规则 |
|------|------|
| **`campaign_run_target_months`** | 配置 **86**（与终局固定灾害 `trigger_month` 一致） |
| **是否「到顶」** | **否**。86 月 **不是** 强制关服日；只是 **最后一考** 的预定月份。此前可照常升公司级、扩图、研发 |
| **胜利后** | 终局灾害结算完成且未破产 → **M14 通关** → 本局结束（首版 **无** 通关后继续的沙盒） |
| **与 I～V 级** | 预期 **II～IV 在 22～63 月间逐步打开**；门槛表在 T37 与灾害月 **联调** |

**时长锚点**：终局 **86 月**（约 7.2 游戏年）。灾害 **间隔参差**（19 / 22 / 23 月），避免「刻度尺」感。若 playtest 仍偏短，整体 **+12 月** 平移各场 `trigger_month`，**不** 增场数。

**体感参考**（非承诺）：熟练玩家 **简单 + 科技熟练度 3** 约 **50～70 分钟** 通关一局；**熟练度 1** 首通可更长。

## 游戏难度

首版 **仅两档**：

| 难度 ID | 显示名 | 设计意图 |
|---------|--------|----------|
| `simple` | 简单 | 更高起始资金、灾害负向 **固定值** 下调、破产前容错 |
| `normal` | 一般 | 基准表；**能运营多久看天意**（事件与灾害 RNG + 玩家决策） |

**不调**核心规则（临水建水电、lit 预算、2 月破产等两档相同）。

难度 **固定偏移** 进 `difficulty_modifiers` 表（整数，T37）：

| 字段 | 简单 `simple` | 一般 `normal` | 说明（玩家向） |
|------|---------------|---------------|----------------|
| `starting_funds_base` | 80 | 80 | 新局开局资金（万） |
| `starting_funds_bonus` | **+40** | 0 | 简单档额外赠送 → 开局 **120** 万 |
| `disaster_cash_penalty_mult_pct` | **75** | **100** | 灾害一次性扣款按 **75%** 结算（整数演算后 floor） |
| `campaign_exam_tier_offset` | **−1** | 0 | 固定灾害的 **考试档位** 下调 1 级（**最低 1 级**，见下） |

**「考试档位」是什么（难度问题 2 的语义）**：每场固定灾害在数据表里标 **`exam_tier` = 1 / 2 / 3**（数字越大越狠：扣款更多、持续 debuff 更重）。选 **简单** 时，实际生效档位 = `max(1, exam_tier + campaign_exam_tier_offset)`，**同一灾害事件模板**、同一固定月份，只改 **强度档位**，不换事件剧情 ID。

## 经营方针（四类）

**教学入口**（非本表方针）：方针屏 **「教学」**（`doctrine_tutorial`）为独立教程关，规则见 [10-onboarding.md](./10-onboarding.md)；**不计**入下表局外等级。

### 总表

| ID | 显示名（占位） | 局内核心特色 | lit 预算 |
|----|----------------|--------------|----------|
| `renewable` | 风光电 | 开局 **储能系统·I**（`storage_1`）已点亮；建设费 **%** 减免 | **受限**（= `doctrine_lit_budget`） |
| `hydro` | 水电 | **临水**；高供能 mult + **可研核电**；靠电网输送 | **受限** |
| `thermal` | 化石能源 | 火/核 **月运维 = 0**；开局 **清洁煤电 + 无害化核废料** 已点亮 | **受限** |
| `tech` | 科技 | **无 lit 上限**、**无线别硬顶**；研发费/工期靠 **熟练度**（见下） | **无上限**（唯一可满科技） |

### 1. 风光电 `renewable`

**储能系统·I～III**（`storage_1～3`）与风光 **·III～·V** 配套；**·I** 含出力 ×2 + 卡 ·III；方针须用 lit 点满 **·II、·III**，但不一次性全送。

| 项 | 规则 |
|----|------|
| 开局点亮（不占 lit 预算） | **`storage_1`（储能系统·I）**：出力 ×2 + 可研风光 ·III；**不**送 `storage_2`（储能系统·II）、`storage_3`（储能系统·III） |
| 建设 | 风光 `build_cost` / `build_duration` 由 **熟练度表** 线性加成（见下）；局内仍送 **储能系统·I** |
| lit 目标（须用满 **14** 点） | `wind_2～5` + `solar_2～5` + **`storage_2`（储能系统·II）、`storage_3`（储能系统·III）** + 电网核心 + `super_hydro` |
| 异线 | **火/核/常规水电** 仅 ·I（开局已 lit）；**不可研 ·II 及以上** |

### 2. 水电 `hydro`

| 项 | 规则 |
|----|------|
| 地图 | **仅** `has_river = true`（**临水**）可建常规水电；**不**放宽选址 |
| 供能 | **常规 / 超级水电** 分档 mult（见下表；[04-energy-supply.md](./04-energy-supply.md)） |
| 核电 | **可研 `nuclear_1～3`**（占 lit；受中心城/都、每城 1 座等 **全局规则**）；中期缓解选址，后期靠 **V 级 `super_hydro`** |
| 建设 | 常规水电、核电设施工期 **−1 月**（熟练度表；下限 1） |
| lit 目标 | `hydro_2～5` + **`nuclear_1～3`** + 电网 + `super_hydro`（15 点内取舍） |
| 异线 | 风/光/火 **仅 ·I**；**核电为本线**（不受「核仅 ·I」硬顶） |

### 3. 化石能源 `thermal`

| 项 | 规则 |
|----|------|
| 开局点亮 | `eco_thermal`、`eco_nuclear` |
| 运维 | 火、核设施 **`monthly_operating_cost = 0`**（仍计建设费、研发费；事件可临时加价） |
| lit 目标 | 保障 `thermal_2～5` + `nuclear_1～3` + 电网核心 + `super_hydro`；风光水 **不可升 tier** |

### 4. 科技 `tech`

| 项 | 规则 |
|----|------|
| lit 上限 | **无**；唯一可点亮 **全部** 可研节点（含全部 `eng_*`） |
| 异线 | **无** tier 硬顶；风/光/火/水/核均可研 ·II～V（仍受公司等级、前置、单队列约束） |
| 建设/运维 | **无** 方针级建设费、工期、月运维加成 |
| 研发经济 | **仅由熟练度表** 决定（下节 **`doctrine_meta_table`**） |

**路线身份（每局）**：**无 lit 顶、无异线硬顶**（可点满科技树）；**无** 发电侧建设/运维加成 → 补偿在 **研发费 % + 工期 −月**。

## 科技点亮预算（非科技方针）

### 统一池 · 自由分配

非科技三方针（风光 / 水电 / 化石）共用 **`doctrine_lit_budget = 15`**（单局 lifetime 总点亮次数）。

| 规则 | 说明 |
|------|------|
| 计数 | 任意可研节点 `researching → lit` 均占用 **1** 点（**不分** 主线 / 经营） |
| 不计入 | 全局开局 ·I；风光方针额外开局 **`storage_1`（储能系统·I）** |
| 玩家选择 | 在 **异线硬顶** 与 **公司等级 / 前置** 约束下，**自由** 组合主线节点与 `eng_*` |
| **`tech` 方针** | 预算 **不生效**（∞） |

**上限推导**：风光满线 **最少 14** 点（见下表）+ **1** 点灵活位（可点 `eng_green_pr` 等，或换取舍）→ **15**。

### 风光满线参考（14 点，非强制）

**开局已 lit（0 点）**：`wind_1`、`solar_1`、`storage_1`（储能系统·I）

**若要点满风光典型终局**（占 14 点）：

| 节点 | 数量 |
|------|------|
| `wind_2`～`wind_5` | 4 |
| `solar_2`～`solar_5` | 4 |
| `storage_2`（储能系统·II）、`storage_3`（储能系统·III） | 2 |
| `grid_regional`、`grid_backbone`、`uhv_transmission` | 3 |
| `super_hydro` | 1 |
| **小计** | **14** |

**第 15 点** 示例（自由选，非唯一解）：

| 取舍示例 | 说明 |
|----------|------|
| **满线 + `eng_green_pr`** | 14 + 1；风光全环保时 SV 加成最顺 |
| **满线 + `eng_risk_reserve`** | 偏灾害战役生存 |
| **省 1 主线 + 2 个 `eng_*`** | 如不做 `super_hydro`，换施工/集采等（仅 15 点内） |

水电 / 化石 **同一 15 点池**：本线 + 电网 + 超水电 + 若干 `eng_*` 由玩家自行搭配。

### 异线 tier 硬顶

非 `tech` 方针时，**非本线** 发电节点 **不可研 ·II 及以上**（`locked`）。**水电方针例外**：`nuclear_*` **视为本线**，可研 ·II～III。

| 方针 | 硬顶（不可研 ·II+） | 本线（可研至 ·V，受公司等级约束） |
|------|---------------------|-----------------------------------|
| `renewable` | `thermal_*`、`hydro_*`、`nuclear_*` | 风、光、储能系统、电网、`super_hydro` |
| `hydro` | `wind_*`、`solar_*`、`thermal_*` | **水电**、**核电**、电网、`super_hydro` |
| `thermal` | `wind_*`、`solar_*`、`hydro_*` | 火、核、电网、`super_hydro`；`eco_*` 局内已 lit |

电网核心、`super_hydro` **不受** 异线硬顶。

### UI

科技树显示（非 `tech` 方针）：**「本局剩余点亮：N / 15」**（`tech` 方针：**无上限**）。

## 方针局外成长（熟练度 1～3）· 定稿表

**玩家向含义**：用某路线 **通关** 后，该路线 **熟练度** 上升（最高 **3**）。**下次再选同一路线** 时，按档位取 **`doctrine_meta_table`**。实现字段 `doctrine_meta_level`；四路线 **分开计**。

| 通关难度 | 熟练度怎么涨 |
|----------|----------------|
| `simple` | 该路线 **+1**（上限 **3**） |
| `normal` | 该路线 **+2**（上限 **3**） |

### 配表原则（定稿）

| 原则 | 说明 |
|------|------|
| **局内 vs 熟练度** | **局内**（每局选该方针必有）：风光开局 **储能系统·I**、化石 0 运维 + 双 ECO、科技无 lit 顶/无异线硬顶、水电仅临水 |
| **熟练度 1 = 核心数值** | **第一次** 选这条路就能感到「路线味道」——表里 **L1 即核心能力的主档位**，不是「几乎没加成」 |
| **2→3 线性平缓** | 每升 1 级 **固定步长** 叠加（见各表 **步长** 行），避免跳变 |
| **封顶** | 熟练度 **3** 为上限；**不** 再叠第四档 |

**Playable v0**：默认熟练度 **1**（已含各路线 **核心 meta 数值**）。

### `doctrine_meta_table`（GDD 定稿，T37 照抄）

**结算**：

```text
建设费（风光 / 火核）：
  final = (base * (100 - build_cost_discount_pct)) // 100    // 仅百分比，无固定「万」减免

研发费（科技）：
  final = (base * research_cost_pct) // 100

工期：
  final_months = max(1, base_months + build_months_delta)   // 或 research_months_delta
```

#### 科技 `tech` · 研发（核心 = 科技树补贴；局内 = 满科技树）

| 熟练度 | `research_cost_pct`（付表价比例） | `research_months_delta` |
|--------|-----------------------------------|-------------------------|
| **1** | **80** | **−1** |
| **2** | **70** | **−2** |
| **3** | **60** | **−3** |

步长：研发费 **每级 −10** 个百分点；工期 **每级多 −1 月**（**下限 1 月**）。

#### 风光 `renewable` · 风光设施建设

| 熟练度 | `build_cost_discount_pct` | `build_months_delta` |
|--------|---------------------------|----------------------|
| **1** | **10** | **−1** |
| **2** | **15** | **−1** |
| **3** | **20** | **−1** |

步长：建设费 **每级 +5** 个百分点（**仅 %**，无固定万）；工期 L1 起 **−1 月**。

#### 水电 `hydro` · 供能 + 建设

**设计意图**：临水选址少 → **常规水电 mult 很高**；靠 **电网输送**；**核电** 占 lit、缓解中期；**V 级超水电** 终局。**超级水电 mult 不随熟练度升级**（仅 L1 档）。

| 熟练度 | 常规水电 `doctrine_hydro_mult` | 超级水电 `doctrine_super_hydro_mult` | 水电/核电 `build_months_delta` |
|--------|--------------------------------|--------------------------------------|--------------------------------|
| **1** | ×**200/100**（**+100%**） | ×**140/100**（**+40%**） | **−1** |
| **2** | ×**220/100**（**+120%**） | ×**140/100** | **−1** |
| **3** | ×**240/100**（**+140%**） | ×**140/100** | **−1** |

步长：常规水电 **每级 +20** 百分点（在 100% 基准上）；超级 **固定 +40%**。

#### 化石 `thermal` · 火/核设施建设

| 熟练度 | 火/核 `build_cost_discount_pct` | 火/核 `build_months_delta` | 月运维 |
|--------|---------------------------------|------------------------------|--------|
| **1** | **10** | **−1** | **0**（局内） |
| **2** | **15** | **−1** | **0** |
| **3** | **20** | **−1** | **0** |

步长：建设费 **每级 +5** 个百分点；运维 **不** 在熟练度重复叠加。

### 四路线 · 熟练度 1 首局体感

| 路线 | 局内（每局必有） | 熟练度 1（核心 meta） |
|------|------------------|------------------------|
| **风光** | **储能系统·I**（×2 出力规则 + 卡 ·III） | 风光建设 **−1 月**、造价 **−10%** |
| **水电** | 仅临水建常规水电 | 常规水电 **×2**、超水电 **×1.4**、工期 **−1 月**、**可研核电** |
| **化石** | 0 运维、双 ECO | 火/核建设 **−1 月**、造价 **−10%** |
| **科技** | 满科技树 | 研发 **8 折**、工期 **−1 月** |

### 四路线 · 熟练度 3 封顶对照

| 路线 | 熟练度 3 |
|------|----------|
| **风光** | 风光造价 **−20%**、工期 **−1 月** |
| **水电** | 常规水电 **×2.4**、超水电 **×1.4**、工期 **−1 月** + 核电线 |
| **化石** | 火/核造价 **−20%**、工期 **−1 月**、0 运维 |
| **科技** | 研发 **6 折**、工期 **−3 月**（min 1） |

## 胜负条件

### 失败：破产

见 [02-economy.md](./02-economy.md#破产)：

- 连续 **2** 个自然月、月度管道 **全部结算完成后** `funds < 0` → **本局失败**。
- 任意一个月末 `funds ≥ 0` → 连续计数 **清零**（贷款、退款、收入、事件补贴等 **任何** 合法手段回正均算）。

### 胜利：撑过固定灾害轴（战役通关）

借鉴《大理石时代》：**单局有一条固定的「灾害日程表」**；经营不善时，灾害会 **放大现金流压力**，促使破产并重开；撑过 **最后一场固定灾害** 且当月末未破产 → **本局通关**。

#### 术语（与 [08-events.md](./08-events.md) 一致）

| 术语 | 含义 |
|------|------|
| **固定灾害** | 本局 **战役通关轴** 上的 **`event_type = disaster`**，在 **`trigger_month` 指定月份** 必定触发；全屏弹窗 + **考试档位** |
| **随机事件** | 表驱动的 **政策 `policy` / 市场 `market`**（及权重池里的其它条目），可在任意月出现，**增益或减益** |
| **战役 / 通关轴** | 仅指 **`campaign_disasters[]` 固定灾害序列**（**4 场**，终局月 **86**），**不是** 随机事件池 |

```text
每月 M11
  → 若 calendar_month == 某场固定灾害的 trigger_month → 触发该场「固定灾害」
  → 随机事件池照常掷骰 → 可能叠加 policy / market（仍受 active ≤ 3 限制）
固定灾害结算完成且未破产 → 继续经营；最后一场（is_final）过关 → M14 通关
```

**设计意图**（对齐大理石时代体感）：固定灾害 = **少量阶段大考**；**发生月份参差**（非等间距刻度尺）；**越狠的考试预告越早**。经营差时，大考 + 随机减益 **叠加**，仍主要通过 **破产** 出局（见下）。

| 项 | 规则 |
|----|------|
| 场数 | **4 场**；`campaign_run_target_months = **86**`（= 终局 `trigger_month`） |
| 触发 | **仅固定月** `trigger_month`；**间隔不必相等** |
| 预警 | 每场 **`warn_lead_months`** 按 **`exam_tier`**（终局可 +2）：**tier 1 → 8 月**，**tier 2 → 10 月**，**tier 3 → 12 月**，**终局 tier 3 → 14 月** |
| 预告 UI | 自 `trigger_month − warn_lead_months` 起显示 **「距××灾害还有 N 月」** |
| 与 company_level | **无硬性绑定**（备考仅为 **建议**，见下） |
| 与随机事件 | **并存**；共用 active ≤ 3 槽 |
| 通关奖励 | 对应路线 **熟练度** +1 / +2（上限 3） |

#### 备考与失败（首版）

| 类型 | 规则 |
|------|------|
| **唯一 Game Over** | **连续 2 月末** `funds < 0`（破产）；**不** 因「未达备考」单独判负 |
| **备考目标** | 每场固定灾害可配 **`exam_brief`**（文案 + 可选条件）：如「建议公司 ≥ III 级」「建议已点亮 `eng_risk_reserve`」 |
| **未达标** | **加重经济惩罚**（如该场 `one_time_cash` 再 ×**125%** 或 `exam_tier` **+1**，上限 3），**不** 立刻删档 |
| **硬门槛**（如「10 月内必须点亮某科技否则失败」） | **首版不做**；需独立倒计时 UX 与豁免规则，留后续版本 |

#### 固定灾害轴（86 月终局 · 4 场，T37 填 `event_id` 与金额）

**节奏**：**参差月表**（相邻间隔 **19 / 22 / 23** 月，非等距）；**1 场 tier 3** + **终局**。

| 序号 | `trigger_month` | 距上场间隔 | `warn_lead_months` | `exam_tier` | 备考摘要（占位） | 备注 |
|------|-----------------|------------|--------------------|-------------|------------------|------|
| 1 | **22** | — | **8** | 1 | 现金缓冲、II 级前后 | 首次大考 · 预告短 |
| 2 | **41** | **19** | **10** | 2 | 供能稳定、考虑 `eng_risk_reserve` | |
| 3 | **63** | **22** | **12** | **3** | 建议 **≥ III 级**、贷款/现金预案 | **难** · 预告最长档 |
| 4 | **86** | **23** | **14** | 3 | 终局前扩网/研发收尾 | **`is_final`** · M14 通关 |

**预警规则**（可写在表行或按 tier 推导）：`warn_lead_months = 6 + exam_tier * 2`；若 `is_final` 且 `exam_tier = 3` → **+2**（得 **14**）。`warn_from_month = trigger_month − warn_lead_months`。

战役表字段：`sequence_index`、`trigger_month`、`warn_lead_months`、`event_id`、`exam_tier`、`exam_brief`、`is_final`、`underprepared_penalty`。

## 整数数值原则（全项目）

与 [META.md §12](../META.md#12-数值原则整数优先) 一致。

### 核心规则

| 项 | 规则 |
|----|------|
| **存档与顶栏** | `funds`、供能 MW、工期月数等 **一律整数** |
| **配置表** | **可写百分比**（如 `build_cost_mult_pct = 85` 表示 85%）或 **固定加减** |
| **结算** | 凡经百分比/乘除得到的金额或 MW，**舍弃小数、只保留整数部分**（`floor`  toward 0；实现：`result = (base * num) // den`） |
| **示例** | 造价 1000、85% → `(1000 * 85) // 100 = 850`；**不** 存 850.0 浮点 |

百分比 **更容易配表**（策划写 85、115）；**运行时绝不保留小数**，避免定式 exploit 与累误差。

### 结算顺序（T22 实现）

```text
base（整数）
  → ± doctrine / event 固定值
  → × 百分比或 mult_num/mult_den（整数演算）
  → // 或 floor 得最终整数
  → 扣款 / 写入存档
```

**供能乘区**仍优先 ×2、×150/100 等 **整数比**；结果 **向下取整** 到 MW 整数。

Playtest 须 **分方针、分难度** 跑通战役表，避免单一建设顺序通吃。
