# 愿景与边界

## 概述

本章定义产品的**定位、平台范围、设计目标**，以及微信小游戏首版的**系统边界**（保留 / 舍弃）。它是 `docs/design/gdd/` 的入口：后续各章展开规则细节，本章不重复公式与界面结构。

玩家扮演能源公司经营者，通过建设、组网、研发与宏观决策，在多个区域满足供能需求，在**资金**与**社会价值**之间做长期取舍。

---

## 平台与文档范围

| 项 | 约定 |
|----|------|
| 首发平台 | **微信小游戏** |
| 跨平台方向 | 玩法与工程需为**其它高可移植性小游戏平台**预留空间（如与微信同属一类运行时、抽象层可复用的渠道）；**不考虑**移植成本高的平台 |
| **明确不做** | **PC 版 / 桌面端**；不为此增加玩法复杂度或专属系统 |
| 本文档范围 | 仅玩法与系统设计，**不涉及**引擎、工具链、实现架构 |
| 命名（首版） | 游戏名、玩家主体公司名在 UI 中**使用占位**；不在首版写死品牌文案，后续由配置或品牌文档替换 |
| 技术选型时机 | **待 GDD 全套确认完成**（`gdd/` 各章 `locked` 且 `gdd/README.md` 索引就绪，对应任务 T12）后，再编写 `engineering/stack.md`（T42） |

跨平台时**不**扩展玩法深度，仅适配发行与 SDK 差异；复杂度上限仍以单局小游戏会话为准。

---

## 产品定位

| 维度 | 定义 |
|------|------|
| 类型 | 轻策略经营游戏 |
| 核心题材 | 能源建设与区域供能 |
| 时间节奏 | **静态操作**：玩家操作时时间不前进了；部署完成后由玩家主动推进 |
| 时间单位 | 以**月**为基础单位推进（详见 [核心循环与时间](./01-core-loop.md)） |

设计态度：**子系统边界主动收紧**——宁可略平淡，也不堆复杂度；只保留影响策略判断的核心系统，不做重度模拟。

**源于现实**：题材与结构 **模仿现实** 中常见形态（如省界 **网状邻接**、能源波动与储能、公司等级扩张）；现实中 **少见** 的模型（如全国省份排成 **单链**）**不作** 默认设计。地图与行政见 [地图与建设位](./05-map-and-slots.md#源于现实地图拓扑)；供能见 [供能与能源类型](./04-energy-supply.md)。

---

## 设计目标

玩家体验上应持续满足以下四点：

1. **每月有明确决策**：每个月都能安排建设、研发、扩张或应对波动，而不是被动等待。
2. **阶段目标清晰**：玩家始终知道当前阶段应优先做什么（供能、社会价值、科技、事件倒计时等）。
3. **节奏有起伏**：通过建设推进、关键节点达成、事件压力形成记忆点，避免长期平淡重复。
4. **复杂度可控**：整体负担适合小游戏平台的会话时长与认知成本。

## 首版系统边界

### 保留（核心骨架）

以下系统构成首版可玩骨架，细节分章见 `gdd/` 目录：

| 系统 | 说明 | 详细章节 |
|------|------|----------|
| 选地区与区域解锁 | 随公司等级逐步解锁可经营区域；未解锁区不可深度经营 | [社会价值与公司等级](./03-social-value.md)、[地图与建设位](./05-map-and-slots.md) |
| 建设施工 | 设施与线路非即时完成；**全局最多 3 在建**；费用与工期按月推进 | [资源与经济](./02-economy.md) |
| 科技研发 | 中型科技树；**单队列**在研；一次付清、可取消返还 | [科技研发](./07-tech.md) |
| 借贷 | **公司界面**、**任意月**可申请；**同时仅 1 笔**未还清贷款；**首版不做收购** | [核心循环与时间](./01-core-loop.md)、[资源与经济](./02-economy.md) |
| 区域电网与主干电网 | 两种固定损耗，不做复杂物理模拟 | [电网](./06-grid.md) |
| 事件节点 | 承担主要经营起伏（资金、收入、研发节奏等） | [事件系统](./08-events.md) |
| 重玩性 | 经营方针 × 难度 × 局外等级 × 灾害战役通关 | [重玩性与方针](./11-replayability.md) |
| 双主资源 | 资金 + 社会价值；长期取舍 | [资源与经济](./02-economy.md)、[社会价值](./03-social-value.md) |
| 新手引导与教程 | **首版必须**；与核心循环衔接 | [新手引导](./10-onboarding.md)（T11a 待写） |
| 激励广告 | **三类**、**单局 10 次硬顶**（免广告期不追加）；失败重开重置 | [公司经营与商业化](./09-year-end-and-monetization.md) |

界面体系为**五类**（城市详细建设 / 区域 / 大地图 / 科技树 / 公司），详见 [核心循环与时间](./01-core-loop.md)；**不以**旧稿「四层 + 独立年度战略屏」为准。

### 舍弃（首版明确不做）

| 舍弃项 | 原因 |
|--------|------|
| **PC / 桌面端版本** | 产品方向为小游戏；不为 PC 预留玩法或复杂度 |
| 手动画每一段线路 | 操作负担高，与小游戏节奏不符 |
| 逐个施工单位管理 | 微操过重 |
| 实时流逝时间 | 与「静态操作 + 按月推进」冲突 |
| 复杂电网物理模拟 | 认知与实现成本高；用固定损耗代替 |
| 多套彼此重叠的评分体系 | 目标分散 |
| 多层级需求梯度 | 地区只保留单一供能满足率指标 |
| **成就系统** | 额外目标与界面负担；长期目标由等级、区域、科技、事件承担 |
| **收购上游企业** | 首版不做；业绩联动复杂度高，战略仅保留借贷 |
| **抽卡式负责人 / 多档付费礼包** | **6 元 CFO + 30 元工程总监礼包** + 激励广告；见 [公司经营与商业化](./09-year-end-and-monetization.md) |
| **低可移植性平台** | 工程与玩法不为移植成本高的渠道单独设计 |

## 正式玩法骨架（总览）

以下为当前小游戏版本的**定稿级原则摘要**；具体规则、公式与数值以各分章为准。

| 主题 | 原则 |
|------|------|
| 时间 | 按月推进；社会价值入账与公司等级检视**同在月度结算** |
| 月度反馈 | 不做每月固定结果弹窗；仅在关键节点弹出插画或事件界面 |
| 核心资源 | 仅 **资金**、**社会价值**（顶栏常驻） |
| 社会价值 | 每月重算、可升可降；即升级进度；UI为当前值/下一级门槛；**公司等级只升不降** |
| 供能指标 | 地区唯一核心指标：**供能满足率** |
| 科技 | 研发费用一次付清；研发按月推进；**可随时取消并全额返还** |
| 建设 | 费用按月扣除；工期按月推进；完工后次月生效 |
| 电网 | 仅两种固定损耗（区域内 / 主干）；无距离或电压公式 |
| 地图 | **2 都 + 8 区**；都=单城；每省 **4–6** 个节点（**逐省不同**，禁统一 5 城模板） |
| 起伏 | 主要靠**事件**与**灾害战役**（[08-events.md](./08-events.md)、[11-replayability.md](./11-replayability.md)） |
| 胜负 | **灾害战役通关** 胜；**连续 2 月末负资金** 败 |
| 年度节点 | 公司界面贷款（任意月、单笔并发）；**无年报**；大理石式经营快照 |
| 成就 | **无** |
| 商业化 | **激励广告（10 次/局硬顶）** + 首发插屏；后续 **6 元 CFO + 30 元工程总监/免广告 30 天** |

技术实现与工程选型不在本章约定；**GDD 全部 locked 后**方在 `engineering/` 定案（见上文「技术选型时机」）。
