# 项目状态与任务看板

本文件只记录当前产品状态、当前模块和下一步。长期策略见 `DEVELOPMENT-STRATEGY.md`，协作规则见根目录 `AGENTS.md`，历史查 Git。

## 当前产品状态

- 平台与技术：微信小游戏，Cocos Creator 3.x + TypeScript。
- 已有资产：纯 TS 模拟闭环、配置包、业务模块、Cocos 单场景客户端、存档/广告抽象与大量自动化测试。
- 基线质量：规则与类型基线稳定；2026-07-12 审计时 411 个测试、build、边界检查和客户端快速验证均通过。
- 真实完成度：工程原型已成立，产品原型未成立。现有 Cocos 页面是验证规则与接线的临时壳，不能继续作为正式 UI 逐像素修补。
- 当前目标：暂停正式客户端实现，先完成覆盖全流程的移动端产品原型、视觉系统与关键页面设计，再按已验证设计重建玩家界面。

## 当前模块

- 模块：`PRODUCT-PROTOTYPE-01`
- 标题：全流程产品原型与关键页面设计
- 状态：`in_progress`

### 目标

用适合当前阶段的设计工具确定正式产品的信息架构、视觉系统、页面组件和关键交互，形成可点击的完整游戏流程；工具不限定为 Figma，后续 Cocos 实现只按已评审的页面、组件和状态落地，不再围绕临时壳反复微调。

### 输入

- `gdd/00-vision.md`、`gdd/01-core-loop.md` 及各系统 GDD
- `ui/00-screen-map.md`、`ui/art-direction.md` 与各屏 UI 文档
- `features/` 中各页面所需的输入、输出和状态
- 现有客户端只作为已支持行为与数据的参考，不作为页面结构约束

### 输出 / API

- 一套结构清晰、可导出且可交接的设计资产：Foundations、Components、Flows、Screens、Prototype、Handoff。
- 覆盖主菜单、新局设置、城市、区域、世界、科技、公司、事件/结算的页面与关键状态。
- 至少一条可点击首局主流程：新游戏 → 选择方针 → 建设 → 推月 → 理解变化 → 处理压力 → 明确下一目标。
- 一套可复用组件与状态：资源栏、导航、主操作、卡片、设施/地图节点、建设/研发队列、锁定、风险、完成、弹层与反馈。
- 面向 Cocos 的实现标注：尺寸、间距、字体、色彩、层级、状态切换、动效意图和资产拆分。

### 范围

- 390×844 为主设计尺寸，430×932 做响应式复核。
- 页面范围：`screen_main_menu`、`screen_new_game`、`screen_new_game_doctrine`、`screen_city_detail`、`screen_region`、`screen_world_map`、`screen_tech_tree`、`screen_company`、`screen_run_result`。
- 叠加层优先覆盖建设、推月、事件、升级、引导与帮助；其他低频状态可用组件变体表达。
- 先做低/中保真可点击信息架构，再锁定视觉方向和高保真关键页；页面设计与首局流程同步验证。
- 城市、区域和世界地图采用场景优先、上下文操作：默认态不铺经营仪表盘，设施、空位或节点被点选后再渐进披露详情与操作。

### 当前设计基准

- 当前视觉基准：`docs/design/ui/concepts/city-scene-first-glass-direction-v4.png`；详细规则见 `docs/design/ui/art-direction.md`。
- 已确定的是场景美术、彩色白描边图标、半透明玻璃和分级光晕的视觉语言，不锁死按钮语义、入口数量和交互流程。
- 场景页保持克制：静态资源弱发光、可点对象轻发光、选中对象明确发光、主操作使用暖色高光；不能让全部元素长期同等明亮。
- 当前叶片、人物等入口图标只是视觉占位；应先依据真实玩法确定功能，再制作正式图标母版。
- 当前阶段继续使用 Codex 的游戏 UI 设计与图像生成能力；只有需要原生 Figma 组件、Auto Layout、在线协作或正式可点击交付时，才安装并接入 Figma。

### 当前设计任务

沿用 v4 视觉基准，城市页两条关键流程和正式功能图标阶段已经收口；图标清单固定为 `docs/design/ui/assets/icons/icon-manifest-v2.md`，本阶段不再扩充。当前推进“建筑视觉合同与代表建筑”：镜头与光照已经锁定为 A′ 高机位弱透视 + L3 近顶部正午主光，风电·I、光伏·I、火电·I 已进入同一测试场景验证；光伏 v4 采用立式矩形 3×4 电池面、俯仰转轴、水平旋转环和贴地 X 形基座，表达向日式双轴追日能力。v4 同场景稿通过评审后，只为这三种代表设施制作 256—512px 分级母图与缩略图裁切示例，不批量生产其它建筑、完整城市、区域或世界地图资产。

### 不做

- 不继续微调现有 Cocos 临时壳，不在本模块写客户端页面代码。
- 不制作全部城市、设施、事件和插画资产；只做足以验证风格与组件拆分的代表资产。
- 不凭视觉稿新增玩法规则；设计冲突回到对应 GDD 处理。
- 不为每个数值组合单独画静态页；用组件状态、变量和原型分支表达。
- 不把宣传海报或单张概念图当作产品原型交付。

### 验收

- 可交互原型中能从主菜单点击完成首局关键流程，返回与模态关闭行为一致。
- 全部主屏均有默认态，核心页另有空、锁定、在建、风险、完成或反馈态。
- 390×844 与 430×932 无重叠/截断；正文约 16sp 以上；主要触控区约 48×48dp 以上；动态背景上的文字有稳定承载层。
- 组件实例而非复制图层承担共享 UI；颜色、字体、间距和状态命名可直接用于实现。
- 设计评审能回答：玩家当前目标是什么、主操作是什么、动作后发生什么、下一步去哪里。
- 场景页默认态一眼看上去是可观察、可点按的游戏场景，而不是由常驻卡片、图表和底部标签栏组成的 App 页面。
- 本模块仅设计与看板变更，不运行代码测试；验收以交互原型点击、目标尺寸预览和交付检查为准。
