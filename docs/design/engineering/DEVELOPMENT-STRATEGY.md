# 开发策略：七个玩家垂直切片

本文定义长期开发顺序和阶段门。当前模块只看 `PROJECT-TASK-BOARD.md`。

## 核心原则

- 横向分层规定职责：`sim` 负责规则，`modules` 负责编排，客户端负责输入、渲染和反馈。
- 纵向切片规定交付：每次只实现一条贯穿必要层的玩家流程，并在真实 Cocos 预览中验收。
- 旧文件名、旧 HUD、旧 CLI、旧页面壳和静态 token 不属于兼容目标。
- 后续切片可以用开发验收存档快速进入前置状态，但正式整局贯通不能依赖预置状态。
- 玩家可见流程以产品证据为先；自动化保护规则不变量和高价值路径，不替代试玩。

## 切片 1：城市建设与月结反馈

进入城市 → 点建设位 → 比较风电/光伏/火电 → 建设 → 推月 → 完工 → 看懂资金、可靠的每回合净资金估算、供能和 EXP 月结变化。

只做一个城市和一次供能不足类经营压力反馈；不接完整事件系统。

## 切片 2：公司成长与解锁主干

经营城市 → M9 重算公司 EXP 快照 → M10 达到门槛升级 → 展示新解锁内容 → 对应入口刷新。

公司 EXP 是每月覆盖重算的 `social_value_current`，不是累计货币；当前值可下降，等级与已解锁内容不回退。玩家流程展示代表性升级，自动化覆盖 I–V 解锁矩阵。

## 切片 3：科技研发与可见效果

公司达到 II 级 → 打开科技树 → 选择节点 → 支付与等待 → 节点点亮 → 回到城市看到设施 tier 或供能数值发生真实变化。

当前规则没有独立可消费的“科技点”货币；本阶段实现科技节点研发，不凭 UI 图标新增资源系统。电网权限的实际效果在后续地图切片验收。

## 切片 4：区域地图与区域电网

公司达到 III 级并点亮 `grid_regional` → 进入区域 → 选择两座城市 → 建设区域线 → 完工 → 查看供能调剂。

并网岛内城市按相同满足率、按需求比例分配可用电力，不平均分配 MW；固定线损先扣除，在建链路不参与供能。

## 切片 5：事件、灾害与失败

收到预警 → 准备资金/建设/研发 → 灾害激活 → 查看持续效果 → 应对并恢复，或连续两个月月末资金为负而破产。

先接固定灾害和代表性效果组合；同作用域同类型效果按乘法叠加。完整随机事件池延后到内容阶段。

## 切片 6：全国地图与主干电网

查看逐级解锁节点 → 进入区域或都城 → 在枢纽间建设主干 → 完工 → 查看跨区域并网与线损结果。

本切片不包含超级水电和完整全国地理美术。

## 切片 7：超级水电与终局能力

公司达到 V 级并满足科技 → 选择全国战略槽位 → 建设超级水电 → 接入主干 → 查看大规模供能进入并网岛。

开工前必须先补超级水电 Feature、视觉/占地合同和战略槽位交互。超级水电不是城市普通建设设施；未接入主干时保持孤岛。

## 最终整局贯通门

不使用高级预置状态，从 I 级单城开局连续完成：城市建设 → 公司成长 → 科技 → 区域组网 → 灾害应对 → 主干电网 → 超级水电 → 最终灾害 → 通关或破产。

贯通门用于证明存档、解锁、跨切片状态和长期节奏真实连续，不能由七组独立测试替代。

## 每个切片的完成定义

1. 有目标、输入、玩家操作、输出、范围、不做项和验收命令。
2. 使用真实规则与业务状态，不持有第二套 UI 可写状态。
3. 有完整 Cocos 点击路线和目标尺寸截图/录像。
4. 玩家能说出当前目标、刚发生什么和下一步做什么。
5. 规则变化有相应自动化；未改规则不叠加同义测试。
6. 当前切片未通过前，不扩后续系统、页面和批量美术。

## 证据顺序

1. 产品证据：Cocos 点击路线、目标尺寸画面、试玩记录。
2. 行为证据：核心用户路径和规则不变量测试。
3. 结构护栏：类型检查、边界检查和必要构建。

结构护栏通过不代表玩家可见模块完成。
