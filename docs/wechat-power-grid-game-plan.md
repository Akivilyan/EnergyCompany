# 微信小游戏《星际和平能源公司》项目规划

## 1. 项目概述

### 1.1 暂定名称
- 中文名：星际和平能源公司
- 世界观包装名：星际和平能源公司
- 类型：轻策略经营 / 区域建设 / 科技发展
- 平台：微信小游戏

### 1.2 一句话定位
玩家扮演一家跨区域电力建设公司的经营者，在有限资金、技术和社会评价压力下，为不同地形与发展阶段的地区规划发电与输配电体系，平衡成本、供电稳定性、城市繁荣和公众满意度。

### 1.3 核心卖点
- 题材新鲜：以“电力基础设施建设”作为经营核心。
- 决策明确：地形、人口、资源禀赋不同，设备选择有真实策略差异。
- 反馈清晰：资金、科技、社会评价、繁荣度四条主线互相牵引。
- 适配微信小游戏：单局节奏短、操作轻、数值反馈直观、适合碎片化游玩。

## 2. 设计原则

### 2.1 玩法边界
项目应明确做“轻操作、重决策”的经营游戏，而不是微操施工模拟器，也不是超重度城市建造游戏。

建议靠近你提到的“大理石时代”式体验：
- 玩家主要做“战略选择”而不是“施工过程操作”。
- 玩家决定研发方向、投资优先级、区域扩张顺序、供电方案。
- 施工过程以时间条、建设队列、事件反馈表现，不要求逐根电线手动铺设。
- 地图建设以“区域节点”或“线路方案”形式抽象，不做过细道路施工编辑。

不建议靠近“模拟城市”式事无巨细建设，原因如下：
- 微信小游戏操作界面有限，复杂建造会显著增加学习成本。
- 题材核心乐趣在“资源与科技权衡”，不是自由搭建地块。
- 过细的建造系统会大幅增加美术、UI、数值和程序成本。

### 2.2 玩家体验目标
- 3分钟内理解规则。
- 10分钟内完成一轮“建设-供电-结算-升级”的正反馈闭环。
- 每次升级都能感受到明显的可选路线差异。
- 玩家失败时能明确知道问题来自“技术不足”“成本过高”“地区适配错误”还是“社会评价崩塌”。

## 3. 核心玩法设计

### 3.1 核心循环
1. 选择目标区域。
2. 分析区域条件：人口、地形、资源、气候、发展阶段、距离。
3. 选择供电方案：发电类型、线路投资、储能/调峰方案、预算分配。
4. 执行建设并消耗资金与时间。
5. 区域开始供电，结算收入、维护成本、供电稳定性、社会评价。
6. 获得研发点、公司经验和政策/市场反馈。
7. 升级公司等级，解锁新技术、新地区和新政策工具。
8. 进入下一轮区域扩张或旧区域优化。

### 3.2 单局核心决策
- 先覆盖更多区域，还是先做高质量低成本供电。
- 优先发展高回报大城市，还是先抢占偏远地区换取评价与政策奖励。
- 优先投入发电效率，还是电网稳定、储能与运维能力。
- 短期用成熟技术赚钱，还是提前投资未来技术形成中后期优势。

### 3.3 玩家操作颗粒度建议
建议采用“三层操作”：

- 第1层：区域层
  - 选择哪个城市/乡镇/边境地区先建设。
  - 查看该地区需求与推荐方案。

- 第2层：方案层
  - 从若干供电建设方案中选择，或在有限参数内调整。
  - 例如：火电主供 + 低成本线路、风光储一体化、中型水电 + 高压输电。

- 第3层：公司层
  - 研发科技树。
  - 调整公司政策倾向：利润优先、口碑优先、平衡发展。
  - 决定贷款、补贴申请、维护预算。

不建议增加以下复杂操作：
- 单个施工人员分配。
- 每根电线逐段拖拽铺设。
- 单个居民楼或街区级供电布局。
- 太多同时进行的生产链。

## 4. 地图与关卡结构

### 4.1 地图结构建议
采用“中国地貌启发”的架空区域地图，而不是直接使用真实中国行政地图。

原因：
- 避免现实地理和政策表达过于敏感。
- 可以保留“山区、沿海、平原、边境、荒漠、高原”等鲜明差异。
- 更容易进行关卡平衡和美术统一。

建议地图分为 6 大区域带：
- 东部沿海带：人口密集、工业发达、负荷大、风能和核电候选多。
- 中部平原带：人口稳定、火电与太阳能过渡性强、电网扩建收益高。
- 西南山地带：水电潜力大，但建设成本高、施工周期长。
- 北部风原带：风能丰富、人口分散、稳定性挑战高。
- 西部荒漠带：太阳能潜力极强，但远距离输电压力大。
- 边境稀疏带：单用户成本极高，但社会评价与特殊任务价值高。

### 4.2 区域节点类型
- 小型城市
- 大型城市
- 农村聚落
- 偏远哨站/边境村镇
- 工业园区
- 特殊节点：港口、矿区、科研基地、旅游区

### 4.3 推荐关卡推进
- 第一章：单城起步
  - 教学关，理解基础供电与盈利。
- 第二章：城乡并行
  - 引入“评价”和“繁荣度”。
- 第三章：多地形差异
  - 强调设备适配。
- 第四章：大城市高压需求
  - 引入大型负荷、稳定性和调峰。
- 第五章：边远地区攻坚
  - 强调口碑、补贴和长线路成本。
- 第六章：全国级能源结构优化
  - 多区域联动与科技树收束。

## 5. 电力系统抽象设计

### 5.1 发电方式建议首发版本
- 火电：造价适中、稳定性高、维护成本高、社会评价偏低。
- 水电：前期投入高、后期收益稳、强地形依赖。
- 风电：建设较快、波动较大、适合高风资源地区。
- 太阳能：模块化强、适合荒漠/高日照地区、夜间需储能支持。
- 核电：高门槛高收益，后期解锁，用于大城市稳定供电。

### 5.2 不同能源的核心参数
- 初始建设成本
- 发电效率
- 单位供电成本
- 供电稳定性
- 维护成本
- 建设周期
- 地形适配系数
- 环境/社会评价影响
- 解锁等级

### 5.3 建议加入但先轻量抽象的系统
- 输电损耗：距离越远成本越高。
- 电网稳定性：多波动能源组合会降低稳定性。
- 储能/调峰：用于改善风光波动。
- 维护事故：低维护预算带来跳闸、舆论和罚款。

首版不建议过细模拟：
- 实时电压频率。
- 逐小时负荷曲线。
- 复杂潮流计算。

## 6. 经济系统设计

### 6.1 核心资源
- 资金：建设、维护、研发的基础资源。
- 研发点：通过供电成果、任务和里程碑获得。
- 公司经验：用于升级公司等级。
- 社会评价：影响补贴、特殊项目与结算评分。

### 6.2 收益来源
- 基础供电收入
- 城市繁荣增长带来的税费/合作收益
- 完成区域覆盖奖励
- 特殊政策补贴
- 高评价额外奖励

### 6.3 支出项
- 电站建设成本
- 输配电建设成本
- 运维成本
- 研发投入
- 突发事件处理费用
- 贷款利息

### 6.4 经营张力来源
- 钱不够时，是先上便宜方案还是等待更优技术。
- 评价差时，是降价保口碑还是保持利润。
- 大城市收益高但风险大，偏远地区收益低但评分高。

## 7. 评价与繁荣系统

### 7.1 现有想法的整理
你提出的评分方向非常好，尤其是“大城市高分、农村和偏远地区按用户计分”的思路，已经天然形成了“规模收益”和“公共服务价值”的矛盾。

建议把最终评价拆成 4 个维度：
- 覆盖贡献
- 经济效率
- 社会满意
- 可持续发展

### 7.2 覆盖贡献评分建议
可以采用“区域完成分 + 用户服务分”的混合模式，避免纯按城市类型给分过于粗糙。

基础建议：
- 小型城市首次稳定供电：+100
- 大型城市首次稳定供电：+500
- 农村地区：每服务用户 +2
- 偏远地区：每服务用户 +5

建议继续细化为：
- 稳定供电达标额外奖励：+20% 区域分
- 低成本供电额外奖励：+10% 区域分
- 高频停电影响：-10% 至 -40% 区域分
- 严重过载事故：直接扣除区域评价并降低社会口碑

### 7.3 社会评价公式建议
社会评价不建议只看电价，应综合以下因素：
- 电价是否可接受
- 供电是否稳定
- 覆盖是否公平
- 建设方式是否环保
- 是否优先帮助弱势区域

可用简单公式：

社会评价 = 电价满意度 + 稳定性满意度 + 公平覆盖加成 + 绿色能源加成 - 事故惩罚

### 7.4 繁荣度系统建议
- 区域有一个繁荣度 0-100%。
- 稳定供电会持续提升繁荣度。
- 繁荣度上升后人口增长、用电需求增加、收入提高。
- 当繁荣度达到上限后，该区域进入成熟状态，成为稳定现金流节点。

影响繁荣度的因素：
- 覆盖率
- 供电稳定性
- 电价水平
- 是否满足新增需求
- 重大事故与长期缺电

### 7.5 人口增长机制
- 每个区域设基础人口和人口上限。
- 繁荣度越高，人口增长越快。
- 但人口增长也会反向提高电力需求，迫使玩家升级系统。

这会形成一个非常好的经营循环：
供电成功 -> 区域繁荣 -> 人口增长 -> 需求提升 -> 再投资升级

## 8. 科技树设计

### 8.1 科技树定位
科技树应是本项目的核心长期驱动力，也是玩家主要的个性化策略来源。

建议分为 4 条主线：
- 发电技术
- 电网技术
- 运维管理
- 社会政策

### 8.2 研发主线示例

发电技术：
- 高效锅炉
- 中型水轮机优化
- 大型风机
- 光伏阵列升级
- 三代核电

电网技术：
- 长距离输电
- 低损耗线路
- 智能调度
- 区域电网互联

运维管理：
- 标准化施工
- 快速抢修
- 智能巡检
- 事故预警

社会政策：
- 居民补贴方案
- 偏远地区专项资金
- 绿色认证
- 城市合作协议

### 8.3 科技树设计原则
- 每次升级都应让玩家“明确更强”，而不是只有数值小涨。
- 中前期就出现路线分歧，不要全部线性。
- 允许玩家走“高利润火电流”“绿色风光流”“偏远公益流”“大城市核电流”等流派。

## 9. 随机事件与任务系统

### 9.1 随机事件建议
- 极端天气导致发电波动
- 城市用电激增
- 设备老化故障
- 政策鼓励绿色能源
- 居民要求降价
- 工业园区提出高价签约

### 9.2 任务系统建议
- 主线任务：推动公司成长和地图扩张。
- 区域任务：完成某类地区的稳定覆盖。
- 政策任务：在环保或民生指标上达标。
- 限时挑战：在预算内完成指定供电目标。

## 10. 微信小游戏适配建议

### 10.1 为什么适合微信小游戏
- 策略信息可以卡片化，适合手机竖屏或横屏轻操作。
- 单次操作以选择和拖拽为主，不依赖高精度点击。
- 局内结算和成长反馈清楚，适合短时游玩。

### 10.2 推荐产品形态
建议首版采用“章节关卡 + 全局公司成长”的结构。

原因：
- 比完全开放大地图更容易平衡。
- 更适合内容渐进式解锁。
- 更符合微信小游戏前期留存和新手引导需求。

可以采用：
- 外层：全国区域地图
- 内层：单区域建设结算界面
- 长线：公司总部/科技树界面

### 10.3 操作方式建议
- 点击区域节点进入建设。
- 通过卡片选择建设方案。
- 用少量滑杆调整预算偏好。
- 用科技树界面进行长期升级。

## 11. 技术选型建议

### 11.1 客户端框架
建议优先方案：
- 微信小游戏原生框架 + TypeScript + 轻量 2D 渲染方案

可选实现路径：
- 方案 A：微信小游戏原生 + `minigame-canvas-engine` 风格的轻 UI 实现
- 方案 B：Cocos Creator + TypeScript 导出微信小游戏
- 方案 C：LayaAir + TypeScript

推荐优先级：
1. Cocos Creator + TypeScript
2. 微信小游戏原生
3. LayaAir

推荐 Cocos Creator 的原因：
- 更适合 2D 游戏界面、动画和状态管理。
- 编辑器成熟，适合快速搭 UI、地图节点和流程界面。
- 微信小游戏导出链路成熟。
- 后续若增加演出、特效、地图动效会更省成本。

什么时候考虑原生小游戏框架：
- 团队极强前端工程能力。
- 追求极致包体和完全可控的工程结构。
- 游戏表现相对静态，更接近“可交互经营面板”。

### 11.2 编程语言
- TypeScript

原因：
- 数值系统、配置系统、状态机都很适合类型约束。
- 更利于后续多人协作。
- 对微信小游戏生态兼容好。

### 11.3 数据驱动方案
建议采用“配置表驱动”：
- 区域配置表
- 发电设施配置表
- 科技树配置表
- 事件配置表
- 任务配置表

推荐存储方式：
- 开发期：JSON 或 CSV + 构建时转换
- 运行时：JSON

### 11.4 架构建议
- `core/`
  - 核心数值计算、结算、规则系统
- `config/`
  - 游戏配置表
- `modules/map/`
  - 地图与区域节点
- `modules/build/`
  - 建设方案选择与执行
- `modules/company/`
  - 公司成长与科技树
- `modules/ui/`
  - 公共 UI 组件
- `modules/event/`
  - 随机事件与任务系统
- `save/`
  - 存档与本地持久化

### 11.5 后端需求判断
首版建议“弱后端”或“无强依赖后端”：
- 单机存档即可完成核心体验。
- 如需排行榜、活动和登录，可接轻量云开发。

推荐首版方案：
- 微信云开发用于账号、排行榜、云存档、活动配置。
- 核心数值逻辑仍在客户端本地执行。

## 12. 数值设计建议

### 12.1 首版数值复杂度控制
首版应该坚持“少而有差异”的数值，而不是面面俱到。

建议每种发电方式先只保留 6 个关键参数：
- 建设成本
- 发电能力
- 运维成本
- 稳定性
- 地形适配
- 社会评价影响

### 12.2 难度曲线
- 前期：让玩家频繁成功，快速理解差异。
- 中期：开始出现“一个选择解决一面、损失另一面”的张力。
- 后期：要求多区域联动和长期规划。

### 12.3 首版平衡目标
- 不存在绝对最优发电方式。
- 不同区域存在明显推荐解，但允许次优解通关。
- 绿色能源不是绝对强，只在合适地形与科技支持下强。
- 偏远地区虽然利润低，但在评分和政策奖励上具备战略价值。

## 13. 美术与素材方案

### 13.1 美术风格建议
建议采用“简洁地图 + 卡片信息 + 轻科幻包装”的风格。

关键词：
- 清爽
- 理性
- 科技感
- 低复杂度
- 高辨识度

建议视觉方向：
- 地图为扁平化地貌块面。
- 城市、村落、电站采用图标化表现。
- 重点用 UI 和数据反馈体现经营感，而非大量复杂场景。

### 13.2 素材构成
- 地图底图
- 区域节点图标
- 发电设施图标
- 科技树图标
- UI 图标与按钮
- 事件插图
- 结算页面装饰

说明：
- 采购前必须逐项核对授权，尤其是是否允许商业项目、是否要求署名、是否允许二次修改。
- 首版优先采购“图标、按钮、基础 UI”，不要一开始就采购大量场景素材。

### 13.4 适合自己生成的内容
- 发电设施图标套系
- 事件插图
- 章节封面图
- 科技树节点图标
- 宣传图与商店素材

### 13.5 AI 生成素材建议
AI 更适合：
- 统一风格概念图
- 事件卡插画
- 海报和宣传 KV
- 图标初稿

AI 不太适合直接生成最终游戏 UI：
- 容易风格不统一
- 元素尺寸与状态难一致
- 批量修改成本高

建议工作流：
1. 先确定一套视觉关键词与参考图。
2. 用 AI 生成概念草图。
3. 再由设计统一重绘为正式游戏素材。

### 13.6 自研与采购组合建议
- UI 基础控件：采购或自己绘制
- 图标系统：自己统一制作
- 章节插图：AI 概念 + 后期修正
- 地图：自己定制绘制

## 14. 音频建议

首版保持轻量：
- 主界面 BGM：轻科技、轻经营感
- 建设完成音效
- 升级解锁音效
- 警报/事故音效
- 评分结算音效

来源建议：
- [Pixabay Music](https://pixabay.com/music/)
- [Freesound](https://freesound.org/)
- [ZapSplat](https://www.zapsplat.com/)

同样需逐项确认授权。

## 15. 首版功能范围建议

### 15.1 MVP 必做
- 章节关卡地图
- 4-6 类区域节点
- 5 种基础发电方式
- 基础输电距离与损耗
- 资金、评价、繁荣度、研发点系统
- 科技树第一层
- 事件与任务基础框架
- 单机存档
- 新手引导

### 15.2 首版不要做太重
- 实时自由建造大地图
- 太多电站子系统
- 多人合作/对抗
- 复杂交易市场
- 过多剧情文本
- 数十种细分资源

## 16. 开发阶段规划

### 16.1 阶段一：可玩原型
目标：先验证“选地区 -> 选供电方案 -> 结算 -> 升级”是否好玩。

交付：
- 1 张简化地图
- 3 类区域
- 3 种发电方式
- 1 套评分结算
- 1 层科技树

周期建议：2-4 周

### 16.2 阶段二：MVP
目标：形成完整留存闭环。

交付：
- 6 大区域带雏形
- 完整五类发电方式
- 基础事件系统
- 存档与公司成长
- 美术统一第一版

周期建议：4-8 周

### 16.3 阶段三：打磨上线版
目标：补足表现、引导、数值和平衡。

交付：
- 完整新手引导
- 更多科技树分支
- 事件插图与音效
- 商业化点位
- 数据埋点与调优

周期建议：4-6 周

## 17. 商业化建议

微信小游戏适合轻量商业化，建议克制：
- 激励广告：获取一次性研发点、临时政策补贴、加速建设
- 小额内购：外观皮肤、主题地图包、去广告、装饰性总部 UI

不建议首版重度付费：
- 直接卖数值会破坏经营平衡
- 容易影响社会评价与策略乐趣

## 18. 风险与规避

### 18.1 主要风险
- 题材较新，若反馈不直观会显得“像表格”。
- 数值过复杂会劝退微信小游戏用户。
- 地图和电力系统若过抽象，玩家可能感受不到建设成就。

### 18.2 规避策略
- 强化区域建设前后对比。
- 每次供电成功后明确展示“城市亮灯、繁荣上升、人口增长”。
- 保持参数少但反馈强。
- 优先打磨结算页和升级反馈。

## 19. 项目结论

这个项目最适合的方向，不是做成超复杂基础设施模拟器，而是做成：

“以电力建设为题材、以科技树与经营权衡为核心的轻策略微信小游戏。”

最关键的设计判断有三点：
- 轻操作，重决策。
- 地形适配与科技路线是主要乐趣来源。
- 社会评价和经济收益必须形成真正冲突，玩家才会有经营张力。
